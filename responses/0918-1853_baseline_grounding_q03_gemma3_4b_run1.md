## FortiGate 7.6 로그 누수 및 전송 실패 문제 해결 가이드

FortiGate 7.6에서 로그가 쌓이지 않고 로그 서버로 전송되지 않는 문제는 다양한 원인으로 발생할 수 있습니다. 아래는 문제 해결을 위한 점검 순서와 각 단계별 확인 사항, 그리고 가능한 명령어 예시를 포함한 상세 가이드입니다.

**주의사항:**

*   본 가이드는 FortiGate 7.6 환경을 기준으로 작성되었으며, 실제 환경에 따라 점검 순서 및 확인 사항이 달라질 수 있습니다.
*   FortiGate 모델 및 OS 버전에 따라 명령어 및 설정 옵션이 다를 수 있습니다.
*   정확한 명령어 문법을 확신하지 못하는 경우, '정확한 명령어 확인이 필요합니다'라고 답변합니다.
*   문제 해결 과정에서 로그를 캡처하고 분석하는 것이 중요합니다.

**1단계: 기본 점검 (1시간 이내)**

*   **로그 서버 연결 상태 확인:**
    *   로그 서버와 FortiGate 간의 네트워크 연결 상태를 ping을 통해 확인합니다. (정상 통신 확인)
    *   로그 서버의 방화벽 설정으로 FortiGate의 로그 전송 포트(기본적으로 6514)에 대한 트래픽이 차단되지 않았는지 확인합니다.
*   **FortiGate 로그 설정 확인:**
    *   FortiGate GUI에서 로그 설정 (Log Settings)을 확인합니다.
        *   **Log Destination:** 로그 서버 주소 및 포트가 정확하게 설정되었는지 확인합니다.
        *   **Log Format:** 로그 형식이 로그 서버에서 지원하는 형식인지 확인합니다. (예: Syslog, CEF)
        *   **Log Level:** 로그 레벨이 너무 낮게 설정되어 중요한 이벤트가 로그에 기록되지 않는 경우가 있는지 확인합니다. (Debug, Info, Warning, Error 등)
        *   **Log Storage:** 로그 저장 공간이 부족하지 않은지 확인합니다.
*   **FortiGate 시스템 로그 확인:**
    *   FortiGate GUI에서 System 로그 (System > Logs > System)를 확인하여 오류 메시지나 경고 메시지가 있는지 확인합니다.
    *   로그 서버와의 연결 문제, 로그 저장 공간 부족 등의 문제에 대한 정보가 있는지 확인합니다.

**2단계: FortiGate 로그 설정 심층 점검 (2-4시간 이내)**

*   **로그 정책 (Log Policy) 확인:**
    *   로그 정책이 올바르게 구성되어 있는지 확인합니다.
        *   **Log Source:** 로그를 생성할 대상(예: Web Traffic, IPS, Application Control)이 올바르게 선택되었는지 확인합니다.
        *   **Log Destination:** 로그 서버 주소 및 포트가 정확하게 설정되었는지 확인합니다.
        *   **Log Level:** 로그 정책별로 로그 레벨이 설정되어 있는지 확인합니다.
        *   **Log Filter:** 로그 정책에 설정된 필터가 너무 엄격하게 설정되어 중요한 이벤트가 로그에 기록되지 않는 경우가 있는지 확인합니다.
*   **로그 저장 설정 (Log Storage) 확인:**
    *   로그 저장 설정 (Log Storage)에서 로그 저장 공간이 충분한지, 로그 저장 기간이 적절하게 설정되었는지 확인합니다.
    *   로그 저장 설정에서 로그 서버로의 전송 설정이 올바르게 구성되었는지 확인합니다.
*   **FortiGate 로그 서버 설정 확인:**
    *   로그 서버에서 FortiGate로부터의 로그 전송을 수신하도록 설정되어 있는지 확인합니다.
    *   로그 서버의 로그 수신 포트가 FortiGate의 로그 전송 포트와 일치하는지 확인합니다.
    *   로그 서버의 로그 저장 설정이 FortiGate의 로그 형식과 호환되는지 확인합니다.
*   **FortiGate 로그 큐 (Log Queue) 확인:**
    *   로그 큐 (System > Logs > Log Queue)에서 로그가 큐에 쌓이는지 확인합니다. 로그 큐에 로그가 쌓이지 않는다면, 로그가 생성되지 않거나 로그 서버로 전송되지 않는 문제일 가능성이 높습니다.

**3단계: FortiGate 장비 자체 점검 (4-8시간 이내)**

*   **FortiGate 시스템 상태 확인:**
    *   FortiGate의 CPU, 메모리, 디스크 사용량을 확인합니다. 과도한 자원 사용은 로그 생성 및 전송을 방해할 수 있습니다.
    *   FortiGate의 시스템 상태 (System > Status)를 확인하여 오류 메시지나 경고 메시지가 있는지 확인합니다.
*   **FortiGate 재부팅:**
    *   FortiGate를 재부팅하여 일시적인 소프트웨어 문제를 해결합니다. (주의: 재부팅 전에 현재 설정 및 로그를 백업합니다.)
*   **FortiGate 펌웨어 업데이트:**
    *   FortiGate 펌웨어가 최신 버전인지 확인합니다. 펌웨어 버그로 인해 로그 관련 문제가 발생할 수 있습니다.
*   **FortiGate 하드웨어 문제 점검:**
    *   FortiGate의 하드웨어 (디스크, 메모리 등)에 문제가 있는지 확인합니다. (하드웨어 문제 발생 시, 전문가의 도움을 받으세요.)

**4단계: 고급 문제 해결 (8시간 이후)**

*   **FortiGate 로그 캡처 및 분석:**
    *   FortiGate GUI에서 로그 캡처 기능을 사용하여 로그 생성 과정을 캡처합니다.
    *   캡처된 로그를 분석하여 로그가 생성되지 않는 원인을 파악합니다.
    *   `show log event` 명령어를 사용하여 로그 이벤트 생성 과정을 확인합니다. (정확한 명령어 확인이 필요합니다.)
*   **FortiGate 시스템 로그 분석:**
    *   FortiGate 시스템 로그를 자세히 분석하여 로그 관련 오류 메시지나 경고 메시지를 찾습니다.
*   **FortiGate 로그 서버 설정 재확인:**
    *   로그 서버 설정 (Log Server)을 다시 한번 확인하여 FortiGate와의 통신 설정이 올바르게 구성되었는지 확인합니다.
*   **네트워크 트래픽 분석:**
    *   Wireshark와 같은 네트워크 패킷 분석 도구를 사용하여 FortiGate와 로그 서버 간의 통신 트래픽을 분석합니다. 로그 전송 과정에서 문제가 발생하는지 확인합니다.

**명령어 예시 (FortiOS 7.6):**

*   `show log event`: 로그 이벤트 생성 과정을 확인합니다. (정확한 명령어 확인이 필요합니다.)
*   `show log queue`: 로그 큐 상태를 확인합니다. (정확한 명령어 확인이 필요합니다.)
*   `show system status`: 시스템 상태를 확인합니다. (정확한 명령어 확인이 필요합니다.)
