네트워크 장비 전환 시에는 여러 가지 고려 사항이 필요합니다. 먼저 현재 상황을 분석해 보겠습니다.

*   두 장비는 IEEE 802.1Q로 트렁크 구간을 설정했으며 VLAN ID도 동일하므로, VLAN 관련 설정은 일치하고 있습니다.
*   링크 상태는 up이고 LLDP로 서로 인식되기 때문에, 네트워크 연결 자체는 정상적입니다.
*   일부 VLAN만 통신되지 않고, 포트를 올린 뒤부터 간헐적으로 루프성 트래픽이 관측된다면, 이 문제의 원인은 스위치 내부의 VLAN 설정 또는 포트 구성과 관련된 것으로 추정됩니다.

다음은 확인해야 할 사항 및 이전 작업 순서에 대한 제안입니다.

### 1. VLAN 설정 확인

*   각 스위치에서 VLAN을 생성했는지, 그리고 VLAN ID가 일치하는지 확인합니다.
*   VLAN에 속한 포트가 올려졌는지 확인합니다.
*   VLAN Trunking Protocol (VTP) 설정이 있는지 확인합니다. VTP는 VLAN 정보를 다른 스위치로 동기화하는 프로토콜입니다. 만약 VTP가 활성화되어 있다면, VLAN ID가 일치하지 않아도 VLAN 정보가 동기화되므로, VLAN ID를 일치시키는 것이 중요합니다.

    ```bash
    # Cisco IOS XE에서 VLAN 설정 확인
    show vlan
    
    # Junos OS에서 VLAN 설정 확인
    show vlans
    ```

### 2. 포트 구성 확인

*   각 스위치의 포트에 대한 구성이 올바른지 확인합니다.
*   VLAN Trunking을 사용하고 있는 포트의 VLAN PVID(Port VLAN ID)가 올바른지 확인합니다.
*   VLAN Trunking을 사용하는 포트의 VLAN Tagging이 올바른지 확인합니다.

    ```bash
    # Cisco IOS XE에서 포트 구성 확인
    show interface <interface_name> switchport
    
    # Junos OS에서 포트 구성 확인
    show interfaces <interface_name>
    ```

### 3. LLDP 설정 확인

*   LLDP(Link Layer Discovery Protocol)는 네트워크 장비 간에 연결 정보를 교환하는 프로토콜입니다. 만약 LLDP가 비활성화되어 있다면, 스위치들은 서로 인식하지 못할 것입니다.
*   각 스위치에서 LLDP 설정을 확인하고, 필요시 LLDP를 활성화합니다.

    ```bash
    # Cisco IOS XE에서 LLDP 설정 확인
    show lldp neighbors
    
    # Junos OS에서 LLDP 설정 확인
    show lldp neighbors
    ```

### 4. VLAN Filtering 확인

*   VLAN Filtering은 VLAN이 다른 VLAN과 통신할 수 있는지 여부를 결정하는 기능입니다. 만약 VLAN Filtering이 비활성화되어 있다면, VLAN 간에 루프가 생길 수 있습니다.
*   각 스위치에서 VLAN Filtering 설정을 확인하고, 필요시 VLAN Filtering을 활성화합니다.

    ```bash
    # Cisco IOS XE에서 VLAN Filtering 설정 확인
    show vlan filter
    
    # Junos OS에서 VLAN Filtering 설정 확인
    show vlans
    ```

### 이전 작업 순서

1.  **VLAN ID 일치**: VLAN ID가 동일한지 확인하고, 일치하지 않는다면 VLAN ID를 일치시키는 것이 중요합니다.
2.  **포트 구성**: 포트의 VLAN PVID와 VLAN Tagging이 올바른지 확인합니다.
3.  **LLDP 활성화**: LLDP가 비활성화되어 있다면, LLDP를 활성화하여 스위치들이 서로 인식할 수 있도록 합니다.
4.  **VLAN Filtering 활성화**: VLAN Filtering이 비활성화되어 있다면, VLAN Filtering을 활성화하여 VLAN 간의 루프를 방지합니다.

이전 작업은 위 순서에 따라 진행하는 것이 안전합니다. 만약 문제가 여전히 발생한다면, 네트워크 장비의 로그를 확인하거나, 네트워크 분석 도구를 사용하여 문제의 원인을 찾는 것이 좋습니다.
