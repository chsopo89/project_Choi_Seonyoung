FortiGate에서 로그가 쌓이지 않고 로그 서버로 전송되지 않는 문제를 해결하기 위해, 다음과 같은 점검 순서를 따르는 것이 좋습니다. 각 항목은 문제의 원인을 파악하는 데 중요한 요소입니다.

1. **로그 설정 확인 (Log Settings)**  
   - **명령어**: `diagnose log config get`  
   - 로그 설정에서 로그 유형(예: system, traffic, application 등)이 올바르게 설정되었는지 확인합니다.  
   - 로그 전송 대상 서버(예: FortiAnalyzer, FortiSIEM 등)의 IP 주소와 포트가 정확하게 설정되었는지 확인합니다.  
   - 로그 전송 방식(예: TCP, UDP, SSL 등)이 올바르게 설정되었는지 확인합니다.  
   - 로그 전송 주기(예: 실시간, 1분, 5분 등)가 설정되어 있는지 확인합니다.

2. **로그 서버 연결 상태 확인 (Log Server Connectivity)**  
   - **명령어**: `diagnose log server get`  
   - 로그 서버의 IP 주소, 포트, 프로토콜이 올바르게 설정되었는지 확인합니다.  
   - 로그 서버의 상태가 정상인지 확인합니다.  
   - 로그 서버의 포트가 방화벽에서 차단되지 않았는지 확인합니다.  
   - 로그 서버의 로그 수신 설정(예: 로그 포맷, 로그 필터 등)이 올바르게 구성되어 있는지 확인합니다.

3. **로그 전송 상태 확인 (Log Transmission Status)**  
   - **명령어**: `diagnose log status`  
   - 로그 전송 상태를 확인합니다.  
   - 로그 전송 중 오류 메시지가 있는지 확인합니다.  
   - 로그 전송이 중단되었는지, 또는 특정 로그 유형만 전송되지 않는지 확인합니다.

4. **로그 쌓임 상태 확인 (Log Accumulation Status)**  
   - **명령어**: `diagnose log disk usage`  
   - 로그가 로컬에 쌓이는지 확인합니다.  
   - 로그가 쌓이지 않는다면, 로그 저장 경로나 저장 용량 제한 설정이 문제일 수 있습니다.  
   - 로그 저장 경로가 정상적으로 설정되어 있는지 확인합니다.

5. **시스템 상태 및 리소스 확인 (System Status and Resource Check)**  
   - **명령어**: `diagnose sys info`  
   - 시스템의 CPU, 메모리, 디스크 사용량 등을 확인합니다.  
   - 로그 전송이 시스템 리소스 부족으로 인해 중단되었는지 확인합니다.

6. **정책 및 보안 설정 확인 (Policy and Security Settings)**  
   - **명령어**: `config firewall policy`  
   - 로그 전송에 필요한 포트(예: 514, 5140, 80, 443 등)가 정책에서 허용되었는지 확인합니다.  
   - 보안 설정(예: 방화벽, NAT, IP 정책 등)이 로그 전송을 차단하지 않는지 확인합니다.

7. **로그 서버 로그 확인 (Log Server Log Check)**  
   - 로그 서버에서 로그 수신 상태를 확인합니다.  
   - 로그 서버의 로그 수신 로그에서 전송 실패 원인을 확인합니다.  
   - 로그 서버의 로그 포맷이나 필터 설정이 FortiGate의 로그 포맷과 일치하는지 확인합니다.

8. **업데이트 및 패치 확인 (Update and Patch Check)**  
   - FortiOS 버전이 최신인지 확인합니다.  
   - 로그 전송 관련 버그 패치가 적용되었는지 확인합니다.

위 점검 순서를 따라가며, 각 단계에서 문제가 발견되면 해당 항목을 우선적으로 수정하고, 문제가 해결되지 않으면 다음 단계로 이동합니다. 문제가 지속된다면, FortiGate의 디버깅 기능(예: `diagnose log filter` 등)을 활용해 더 구체적인 로그를 확인하는 것도 도움이 됩니다.
