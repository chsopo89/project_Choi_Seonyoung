## FortiGate 7.6 로그 누수 및 전송 실패 문제 해결 가이드

FortiGate 7.6에서 로그가 쌓이지 않고 로그 서버로 전송되지 않는 문제는 다양한 원인으로 발생할 수 있습니다. 아래는 문제 해결을 위한 점검 순서와 각 단계별 확인 사항, 그리고 가능한 명령어 예시를 포함한 상세 가이드입니다.

**주의:** 아래 내용은 FortiGate 7.6 환경을 기준으로 작성되었으며, 실제 환경에 따라 설정 및 동작 방식이 다를 수 있습니다. 정확한 문제 해결을 위해서는 장비 모델, OS 버전, 로그 서버 설정 등을 확인해야 합니다.

**1단계: 기본적인 상태 확인 (1시간 이내)**

* **FortiGate 장비 상태:**
    * **업타임 확인:** FortiGate의 업타임이 정상인지 확인합니다. 업타임이 중단되었다면 전원 문제, 하드웨어 문제 등을 의심해야 합니다.
    * **CPU, 메모리 사용량 확인:** CPU 및 메모리 사용량이 과도하게 높으면 로그 수집 및 전송에 영향을 줄 수 있습니다. `show system resource` 명령어를 사용하여 리소스 사용량을 확인합니다. (정확한 명령어 확인이 필요합니다)
    * **네트워크 연결 상태 확인:** FortiGate와 로그 서버 간의 네트워크 연결 상태를 확인합니다. `ping` 명령어를 사용하여 기본적인 연결 가능성을 확인하고, 패킷 손실 여부, 응답 시간 등을 확인합니다.
* **로그 서버 상태:**
    * **로그 서버 정상 동작 확인:** 로그 서버의 서비스 상태, CPU, 메모리 사용량 등을 확인하여 정상적으로 동작하는지 확인합니다.
    * **로그 서버 설정 확인:** FortiGate에서 설정한 로그 서버 주소, 포트, 인증 정보 등이 정확한지 확인합니다.
* **FortiGate 로그 설정 확인:**
    * **로그 수집 활성화 확인:** FortiGate의 로그 수집 기능이 활성화되어 있는지 확인합니다. `show log config` 명령어를 사용하여 로그 수집 설정을 확인합니다. (정확한 명령어 확인이 필요합니다)
    * **로그 서버 설정 확인:** 로그 서버 주소, 포트, 인증 방식 등이 올바르게 설정되어 있는지 확인합니다.
    * **로그 레벨 확인:** 로그 레벨이 너무 낮게 설정되어 있으면 불필요한 로그가 많이 생성되어 저장 공간 부족 문제를 야기할 수 있습니다. 로그 레벨을 적절하게 조정합니다. (예: `set log system loglevel info`) (정확한 명령어 확인이 필요합니다)

**2단계: 로그 수집 설정 점검 (2-3시간 이내)**

* **로그 수집 정책 확인:** FortiGate에서 설정된 로그 수집 정책이 올바르게 구성되어 있는지 확인합니다. 정책에 포함된 이벤트 유형, 로그 레벨, 로그 저장 기간 등이 예상과 일치하는지 확인합니다.
* **로그 수집 큐 확인:** 로그 수집 큐에 로그 데이터가 누적되어 있는지 확인합니다. 큐가 가득 차면 로그 전송이 지연될 수 있습니다. `show log queue` 명령어를 사용하여 큐 상태를 확인합니다. (정확한 명령어 확인이 필요합니다)
* **로그 전송 설정 확인:** 로그 전송 설정 (예: SFTP, HTTP, SMB)이 올바르게 구성되어 있는지 확인합니다. 전송 속도 제한, 인증 정보 등이 문제가 될 수 있습니다.
* **로그 전송 큐 확인:** 로그 전송 큐에 로그 데이터가 누적되어 있는지 확인합니다. 큐가 가득 차면 로그 전송이 지연될 수 있습니다.

**3단계: 로그 서버와의 통신 점검 (3-4시간 이내)**

* **방화벽 규칙 확인:** FortiGate와 로그 서버 간의 통신을 위한 방화벽 규칙이 올바르게 설정되어 있는지 확인합니다. 로그 서버 주소, 포트, 프로토콜 등이 규칙에 포함되어 있는지 확인합니다.
* **로그 서버 인증 확인:** FortiGate에서 로그 서버로 전송되는 로그 데이터에 대한 인증 설정이 올바르게 구성되어 있는지 확인합니다. (예: 사용자 이름, 비밀번호, 인증서)
* **로그 서버 로그 확인:** 로그 서버의 로그를 확인하여 FortiGate에서 전송되는 로그 데이터가 정상적으로 수신되는지 확인합니다. 로그 서버 로그는 FortiGate에서 설정한 로그 전송 방식에 따라 다릅니다.
* **MTU 설정 확인:** FortiGate와 로그 서버 간의 MTU 설정이 호환되는지 확인합니다. MTU 설정 불일치는 패킷 손실 및 로그 전송 실패를 야기할 수 있습니다.

**4단계: 고급 문제 해결 (4시간 이후)**

* **로그 수집기 문제 확인:** 로그 수집기가 정상적으로 동작하는지 확인합니다. 로그 수집기의 로그를 확인하여 오류가 있는지 확인합니다.
* **네트워크 트래픽 분석:** Wireshark와 같은 네트워크 패킷 분석 도구를 사용하여 FortiGate와 로그 서버 간의 통신 트래픽을 분석합니다. 트래픽 손실, 패킷 손상, 응답 시간 지연 등을 확인합니다.
* **FortiGate 재부팅:** FortiGate를 재부팅하여 일시적인 문제를 해결합니다.
* **FortiOS 업데이트:** FortiOS 7.6 버전이 최신 버전인지 확인하고, 최신 버전으로 업데이트합니다.

**추가적인 점검 사항:**

* **로그 저장 공간 부족:** FortiGate의 로그 저장 공간이 부족하면 로그 수집 및 전송이 중단될 수 있습니다. 로그 저장 공간을 늘리거나 불필요한 로그를 삭제합니다.
* **로그 서버 과부하:** 로그 서버가 과부하되면 로그 전송이 지연될 수 있습니다. 로그 서버의 성능을 개선하거나 로그 전송 설정을 조정합니다.
* **시간 동기화:** FortiGate와 로그 서버의 시간 동기화가 제대로 이루어지지 않으면 로그 전송에 문제가 발생할 수 있습니다. NTP 서버를 사용하여 시간 동기화를 설정합니다.

**참고:**

* 위에서 제시된 명령어는 FortiGate 7.6 환경에서 사용 가능한 명령어 예시입니다. 실제 환경에 따라 명령어 문법이 다를 수 있습니다.
* FortiGate의 로그 설정 및 관리 방법은 Fortinet 공식 문서를 참조하십시오.
