네트워크 장비 전환 시에는 여러 가지 고려 사항이 필요합니다. 먼저 현재 상황을 분석해 보겠습니다.

*   두 장비는 IEEE 802.1Q로 트렁크 구간을 설정했으며 VLAN ID도 동일하므로 VLAN 관련 설정은 정상적입니다.
*   링크 상태는 up이고 LLDP로 서로 인식되기 때문에 네트워크 연결 자체는 정상적입니다.
*   일부 VLAN만 통신되지 않고 포트를 올린 뒤부터 간헐적으로 루프성 트래픽이 관측된다.

이러한 현상을 해결하기 위해 다음 순서에 따라 확인 및 작업을 진행할 수 있습니다.

### 1. VLAN 통신 문제

#### **확인**

*   각 VLAN의 통신 문제가 발생하는지 확인합니다. VLAN ID가 동일하고 IEEE 802.1Q로 설정되어 있으므로, VLAN 관련 설정은 이미 확인된 바 있습니다. 하지만 VLAN ID가 동일하더라도 VLAN 태그가 잘못된 경우 또는 VLAN이 비활성화된 경우 통신이 불가능합니다.
*   VLAN ID가 동일하지만 VLAN 태그가 잘못된 경우를 확인합니다. Cisco Catalyst 스위치에서 `show vlan` 명령어를 사용하여 VLAN ID와 VLAN 이름을 확인할 수 있습니다.

    ```bash
    show vlan
    ```

    Juniper 스위치에서는 `show vlans` 명령어를 사용합니다.

    ```bash
    show vlans
    ```

#### **수정**

*   VLAN ID가 동일하고 VLAN 이름도 일치하는지 확인한 후, VLAN이 비활성화되지 않은 것을 확인합니다.
*   VLAN이 비활성화된 경우 활성화합니다.

### 2. 루프성 트래픽

#### **확인**

*   루프성 트래픽이 발생하는 포트를 확인합니다. Cisco Catalyst 스위치에서 `show spanning-tree` 명령어를 사용하여 스패닝 트리 관련 정보를 확인할 수 있습니다.

    ```bash
    show spanning-tree
    ```

    Juniper 스위치에서는 `show spanning-tree` 명령어를 사용합니다.

    ```bash
    show spanning-tree
    ```

*   루프가 발생한 포트에 대한 VLAN 태그를 확인합니다. IEEE 802.1Q로 설정된 트렁크 구간에서 VLAN ID가 동일해야 하므로, 이 경우에는 VLAN ID가 잘못된 것이 아닌 다른 문제일 가능성이 높습니다.
*   LLDP 프로토콜을 통해 서로 인식되는지 확인합니다. Cisco Catalyst 스위치에서 `show lldp neighbors` 명령어를 사용하여 LLDP 관련 정보를 확인할 수 있습니다.

    ```bash
    show lldp neighbors
    ```

    Juniper 스위치에서는 `show lldp neighbors` 명령어를 사용합니다.

    ```bash
    show lldp neighbors
    ```

#### **수정**

*   루프가 발생한 포트에 대한 VLAN 태그를 확인하고, 필요시 수정합니다.
*   LLDP 프로토콜이 잘못된 경우 LLDP 설정을 확인하고 수정합니다.

### 3. 이전 작업 순서

#### **순서**

1.  VLAN 통신 문제를 해결합니다.
2.  루프성 트래픽을 해결합니다.
3.  네트워크 장비 전환을 완료합니다.

#### **주의사항**

*   네트워크 장비 전환 시에는 모든 구성이 동일해야 하므로, 각 장비의 구성이 일치하는지 확인합니다.
*   전환 후에도 문제가 발생할 수 있으므로, 주기적으로 네트워크 상태를 모니터링하여 문제를 사전 예방합니다.

네트워크 장비 전환은 복잡한 작업이므로, 이러한 순서에 따라 진행하면 안전하고 효율적인 결과를 얻을 수 있습니다.
