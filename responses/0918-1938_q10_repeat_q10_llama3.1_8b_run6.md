네트워크 장비 전환 시에는 여러 가지 고려 사항이 필요합니다. 먼저 현재 상황을 분석해 보겠습니다.

*   두 장비는 IEEE 802.1Q로 트렁크 구간을 설정했으며 VLAN ID도 동일하므로 VLAN 관련 설정은 정상적입니다.
*   링크는 up이고 LLDP로 서로 인식되기 때문에 네트워크 연결 자체는 정상적입니다.
*   일부 VLAN만 통신되지 않고 포트를 올린 뒤부터 간헐적으로 루프성 트래픽이 관측된다.

이러한 현상을 해결하기 위해 다음 순서로 확인 및 작업을 진행할 수 있습니다.

### 1. VLAN 통신 문제

*   **VLAN 통신 문제** : VLAN 통신이 제대로 이루어지지 않는다면, VLAN ID가 동일하고 IEEE 802.1Q로 설정된 경우에는 일반적인 VLAN 관련 설정 오류가 아닌 다른 문제일 가능성이 높습니다. 이때는 VLAN 통신에 영향을 주는 다른 설정이나 장비의 상태를 확인해야 합니다.
*   **포트 올리기 이후 루프성 트래픽** : 포트를 올린 뒤부터 루프성 트래픽이 관측된다면, 이는 네트워크 연결 자체가 문제가 아니라, 스위치 내부에서 발생하는 문제일 가능성이 있습니다.

### 2. 스위치 내부 확인

*   **스위치 내부 상태 확인** : 스위치 내부에서 발생하는 문제를 해결하기 위해, 각 스위치의 내부 상태를 확인합니다. 이때는 스위치의 로그 파일을 확인하거나, 스위치 내부의 모니터링 도구를 사용하여 문제를 파악할 수 있습니다.
*   **스위치 설정 확인** : 스위치의 설정을 확인하여, VLAN ID, 트렁크 구간, LLDP 등과 같은 관련 설정이 올바르게 구성되어 있는지 확인합니다.

### 3. 네트워크 연결 확인

*   **네트워크 연결 확인** : 네트워크 연결 자체가 정상적인지 확인합니다. 링크는 up이고 LLDP로 서로 인식되기 때문에 일반적인 네트워크 연결 오류일 가능성이 낮습니다.

### 4. 장비 전환 순서

*   **장비 전환 순서** : 장비를 이전할 때는 일반적으로 다음과 같은 순서로 진행합니다.
    *   첫 번째 단계: 기존 장비의 VLAN ID, 트렁크 구간, LLDP 등과 같은 관련 설정을 백업하고, 새로운 장비에 복원합니다.
    *   두 번째 단계: 새로운 장비에서 VLAN ID, 트렁크 구간, LLDP 등과 같은 관련 설정을 구성합니다.
    *   세 번째 단계: 네트워크 연결을 확인하고, 문제가 발생하지 않는지 확인합니다.

### 5. 명령어

*   **명령어** : 위에서 설명한 순서대로 확인 및 작업을 진행할 때, 다음 명령어를 사용할 수 있습니다.

    ```bash
    show vlan
    show trunk
    show lldp neighbors
    ```
    
    이때는 명령어의 정확한 문법이 확신되지 않으므로, 각 장비의 OS에 맞게 확인해야 합니다.

### 결론

네트워크 장비 전환 시에는 여러 가지 고려 사항이 필요합니다. VLAN 통신 문제, 스위치 내부 상태, 네트워크 연결 등 다양한 요인을 확인하고, 문제가 발생하지 않는지 확인하는 것이 중요합니다. 또한, 장비 전환 순서도 중요한 부분입니다. 위에서 설명한 순서대로 진행하면, 문제를 해결할 수 있습니다.
