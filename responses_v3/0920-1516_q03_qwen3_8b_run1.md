1) **FortiGate에서 로그 이벤트 자체가 생성되고 있는지**  
   - 점검 순서: 먼저 로그 이벤트가 실제로 발생하고 있는지 확인해야 합니다. 예를 들어, 방화벽 정책을 통해 트래픽이 통과되거나 차단되는 경우, 해당 이벤트는 로그로 기록되어야 합니다.  
   - 사용할 수 있는 명령어: `diagnose firewall policy list` 또는 `diagnose log filter <log_type>` (예: `diagnose log filter 6`)  
     - `diagnose log filter 6`은 시스템 이벤트(예: 보안 위협, 인증 실패 등)를 필터링하여 확인합니다.  
     - `diagnose firewall policy list`는 방화벽 정책의 활성 상태와 트래픽 통과 여부를 확인합니다.  
   - **결과 분석**: 로그 이벤트가 생성되지 않으면 문제는 로그 생성 단계에서 발생할 수 있습니다. 예를 들어, 정책이 비활성화되었거나, 로그 수집이 비활성화된 경우입니다.

2) **생성된 로그가 로컬 저장 또는 메모리 처리 단계까지 도달하는지**  
   - 점검 순서: 로그 이벤트가 생성되었다면, 해당 로그가 로컬에 저장되거나 메모리에 임시 보관되는지 확인해야 합니다.  
   - 사용할 수 있는 명령어: `diagnose log list`  
     - 이 명령어는 현재 시스템에서 수집 중인 로그를 목록으로 표시합니다.  
   - **결과 분석**: 로그가 로컬에 저장되지 않으면 문제는 로그 수집 설정(예: `log setting`) 또는 메모리 용량 부족 등에서 발생할 수 있습니다.

3) **외부 로그 서버로 전송을 시도하고 있는지**  
   - 점,검 순서: 로그가 로컬에 저장되더라도 외부 서버로 전송되는 과정에서 문제가 생길 수 있습니다.  
   - 사용할 수 있는 명령어: `diagnose log export`  
     - 이 명령어는 로그를 외부 서버로 전송하는 동작을 확인할 수 있습니다.  
   - **결과 분석**: 전송이 실패하거나 중단된 경우, 설정 오류(예: 서버 주소, 포트, 프로토콜) 또는 네트워크 문제 등이 원인일 수 있습니다.

4) **FortiGate에서 실제 로그 패킷이 송신되는지**  
   - 점검 순서: 로그가 외부 서버로 전송되려면 실제로 로그 패킷이 생성되고 네트워크를 통해 전송되어야 합니다.  
   - 사용할 수 있는 명령어: `diagnose log filter 10` (로그 패킷을 필터링하여 확인)  
     - 이 명령어는 로그 패킷의 존재 여부를 확인합니다.  
   - **결과 분석**: 패킷이 생성되지 않거나, 전송 중단 시점에서 문제가 발생했음을 알 수 있습니다.

5) **로그 서버가 해당 패킷을 실제로 수신하는지**  
   - 점검 순서: FortiGate에서 패킷을 송신하더라도 로그 서버가 정상적으로 수신하지 않는 경우도 있습니다.  
   - 사용할 수 있는 명령어: 로그 서버 측에서 `tcpdump` 또는 `netstat` 등을 통해 패킷 수신 여부 확인 (FortiOS 내에서는 직접 확인 불가)  
     - 예: `tcpdump -i eth0 port 514` (UDP 514 포트로 들어오는 패킷 확인)  
   - **결과 분석**: 서버 측에서 패킷이 수신되지 않으면 네트워크 설정, 방화벽 규칙, 포트 전달 문제 등이 원인일 수 있습니다.

6) **각 단계의 결과에 따라 문제를 생성·저장·전송·수신 중 어느 구간으로 좁힐 수 있는지**  
   - 로그 이벤트가 생성되지 않거나, 로컬 저장되지 않으면 문제는 로그 생성 또는 수집 설정에서 발생합니다.  
   - 로컬 저장되지만 외부 전송 시도가 실패하거나 패킷 송신이 없으면 문제는 전송 설정 또는 네트워크 연결에서 발생합니다.  
   - 패킷이 전송되었으나 서버 측에서 수신되지 않으면 문제는 서버 설정, 방화벽 규칙, 포트 전달 등에서 발생합니다.  

**요약**:  
- **로그 생성 확인 → 로컬 저장 여부 → 전송 시도 → 패킷 송신 여부 → 서버 수신 여부** 순으로 점검해야 합니다.  
- 각 단계별로 명령어를 사용하여 문제 구간을 좁히고, 원인을 파악할 수 있습니다.  
- 재부팅이나 초기화 등의 조치는 원인을 파악하기 전에는 권장하지 않습니다.
