## FortiGate IPsec VPN Phase Down/Up 문제 진단 및 해결 방안 (FortiOS 7.6)

현재 FortiGate 두 대 사이에 구성된 IPsec VPN 연결에서 Phase 1 & 2 관련 down/up 로그가 반복적으로 발생하고 연결 상태가 끊겼다가 다시 형성되는 현상이 관찰되고 있습니다. 단순히 전체 설정을 재검토하는 것보다, 문제의 근본적인 원인을 파악하기 위한 체계적인 접근 방식이 필요합니다. 아래는 단계별 진단 및 해결 방안입니다.

**1. 문제 분석: Phase 1 vs. Phase 2**

* **초기 점검:** 문제 발생 빈도와 로그 내용을 면밀히 분석하여 Phase 1 또는 Phase 2 중 어느 단계에서 문제가 발생하는지 우선적으로 판단해야 합니다. 일반적으로 Phase 2 관련 오류가 더 자주 발생하며, 이는 보안 정책 설정이나 암호화 키 관리 문제로 인해 발생할 수 있습니다.
* **추천 순서:** 먼저 Phase 2 관련 오류를 집중적으로 검토하고, Phase 2 문제 해결에 실패하면 Phase 1을 점검합니다.

**2. FortiGate 간 설정 비교 항목**

다음은 양쪽 FortiGate에서 서로 비교해야 하는 주요 설정 항목입니다. (FortiOS 7.6 기준)

| 카테고리          | Phase 1                                  | Phase 2                                    |
|------------------|-------------------------------------------|---------------------------------------------|
| **VPN Policy**    | VPN Policy Name, Tunnel Mode, Protocol  | VPN Policy Name, Tunnel Mode, Protocol       |
| **IKE Settings** | IKE Version, Encryption Algorithm, Hash Algorithm, DH Group, Lifetime | IKE Version, Encryption Algorithm, Hash Algorithm, DH Group, Lifetime |
| **IPsec Settings**| ESP Protocol, SA Lifetime, PFS Algorithm | ESP Protocol, SA Lifetime, PFS Algorithm      |
| **Local Network** | Local IP Address, Subnet Mask            | Local IP Address, Subnet Mask               |
| **Remote Network**| Remote IP Address, Subnet Mask           | Remote IP Address, Subnet Mask                |
| **Authentication**| Pre-Shared Key (PSK) 또는 Certificate     | Pre-Shared Key (PSK) 또는 Certificate       |

**3. 정상 통신 중 down/up 반복 발생 원인 후보 및 확인 방법**

정상 통신이 가능한 상황에서 Phase Down/Up 로그가 반복적으로 발생하는 것은 다음과 같은 원인으로 인해 발생할 수 있습니다.

* **3.1. SA Lifetime 설정 불일치:** IKE SA와 ESP SA의 Lifetime 설정이 서로 일치하지 않으면 주기적인 연결 재협상을 유발하여 다운/업 루프를 생성할 수 있습니다.
    * **확인 방법:** `config vpn ipsec ike` 및 `config vpn ipsec esp` 명령어를 사용하여 각 SA의 Lifetime 값을 비교합니다.  두 값의 차이가 3초 이내로 지속될 경우, Lifetime 설정을 조정해야 합니다. (정확한 명령어 또는 설정값 확인이 필요합니다.)
* **3.2. 동적 IP 주소 문제:** VPN 터널을 통해 통신하는 쪽의 IP 주소가 DHCP 등으로 인해 변경되는 경우, IPsec SA가 더 이상 해당 IP 주소를 인식하지 못하여 다운/업 루프를 생성할 수 있습니다.
    * **확인 방법:** VPN 터널을 통해 통신하는 장비의 IP 주소 변경 이력을 확인하고, FortiGate에서 해당 IP 주소를 고정 IP로 설정하거나, DHCP 옵션 필터링을 통해 IPsec SA 연결에 영향을 미치는 IP 주소 범위를 제한해야 합니다. (정확한 명령어 또는 설정값 확인이 필요합니다.)
* **3.3. 네트워크 간 패킷 손실 및 재전송:** 네트워크 구간에서 패킷 손실이 발생하면 IPsec SA가 이를 감지하고 SA를 종료하여 다운/업 루프를 생성할 수 있습니다.
    * **확인 방법:**  `show logging` 명령어를 사용하여 네트워크 구간의 패킷 손실 관련 로그를 확인합니다. 또한, `ping` 또는 `traceroute` 명령어를 사용하여 네트워크 구간의 통신 상태를 점검합니다.
* **3.4. FortiGate CPU/Memory 과부하:** FortiGate의 CPU 또는 메모리 사용량이 과도하게 높으면 IPsec SA 연결에 영향을 미쳐 다운/업 루프를 유발할 수 있습니다.
    * **확인 방법:** `show system resource` 명령어를 사용하여 CPU 및 메모리 사용량을 모니터링하고, 불필요한 프로세스나 서비스를 중단하여 리소스를 확보합니다. (정확한 명령어 또는 설정값 확인이 필요합니다.)
* **3.5. IKE  정책 충돌:** Phase 1에서 설정된 IKE 정책과 Phase 2에서 설정된 보안 정책 간에 충돌이 발생하면 SA 연결이 끊어질 수 있습니다.
    * **확인 방법:**  `config vpn ipsec ike` 및 `config vpn ipsec esp` 명령어를 통해 각 단계별 설정값을 면밀히 검토하고, 서로 호환되는 설정을 사용하도록 조정합니다. (정확한 명령어 또는 설정값 확인이 필요합니다.)

**4. 원인 후보 제거를 위한 관측 결과**

* **로그 분석:** FortiGate 로그(System Log, VPN Log 등)를 상세하게 분석하여 문제 발생 시점의 네트워크 상태, 설정 값, 오류 메시지 등을 파악합니다.
* **네트워크 트래픽 모니터링:** Wireshark 등의 패킷 분석 도구를 사용하여 IPsec 터널을 통과하는 패킷의 내용을 캡처하고 분석하여 문제 발생 원인을 규명합니다.
* **FortiGate 성능 모니터링:** CPU, 메모리, 디스크 I/O 등의 리소스 사용량을 지속적으로 모니터링하여 과부하가 발생하는 부분을 확인합니다.

**5. 설정 변경 조건 및 종류**

* **SA Lifetime 조정:**  Phase 2 다운/업 루프가 지속되는 경우, IKE SA와 ESP SA의 Lifetime 값을 3초 단위로 점진적으로 늘려가면서 안정적인 연결 상태를 유지할 수 있는 최적의 값을 찾습니다. (정확한 명령어 또는 설정값 확인이 필요합니다.)
* **고정 IP 설정:** VPN 터널을 통해 통신하는 쪽의 IP 주소가 동적으로 할당되는 경우, FortiGate에서 해당 IP 주소를 고정 IP로 설정하거나, DHCP 옵션 필터링을 통해 IPsec SA 연결에 영향을 미치는 IP 주소 범위를 제한합니다. (정확한 명령어 또는 설정값 확인이 필요합니다.)
* **보안 정책 조정:** Phase 1 및 Phase 2에서 설정된 보안 정책 간의 충돌이 발생하는 경우, 서로 호환되는 설정을 사용하도록 조정합니다. (정확한 명령어 또는 설정값 확인이 필요합니다.)
