1. 실제 데이터 통신과 관리 화면의 VPN 상태 표시가 서로 다를 수 있는 이유는 두 가지 경우가 있습니다.

- 첫 번째 경우: VPN 연결은 성공적으로 구성되어 있지만, 관리 화면에서 표시되는 상태가 disable로 나타날 수 있습니다. 이는 일반적으로 VPN 연결이 활성화되었지만, 현재 연결이 사용되지 않고 대기 상태에 있는 경우입니다.
- 두 번째 경우: VPN 연결이 실패했거나, 구성 오류로 인해 연결이 끊겨있는 경우에도 관리 화면에서 disable로 표시될 수 있습니다.

2. Phase 1과 Phase 2 중 어떤 상태를 각각 확인해야 하는지?

- Phase 1: IKE (Internet Key Exchange) 프로토콜을 통해 암호화된 키를 교환하는 단계입니다. 이 단계의 성공 여부는 VPN 연결의 초기화에 영향을 줍니다. 일반적으로 Phase 1의 상태를 확인하여 VPN 연결의 초기화 여부를 파악합니다.
- Phase 2: ESP (Encapsulating Security Payload) 프로토콜을 통해 데이터를 암호화하고 전달하는 단계입니다. 이 단계의 성공 여부는 실제 데이터 통신의 가능성에 영향을 줍니다.

3. NetScreen과 FortiGate 양쪽에서 서로 비교해야 할 VPN 설정 항목은 다음과 같습니다.

- Peer ID 및 Pre-shared Key: 두 장비 간의 인증 정보가 일치하는지 확인합니다.
- IPsec 정책 및 필터링 규칙: 두 장비 간의 통신 허용 여부와 필터링 규칙이 일치하는지 확인합니다.
- IKE 정책 및 프로토콜: 두 장비 간의 IKE 프로토콜 및 정책이 일치하는지 확인합니다.

4. 상태 표시 문제인지 실제 협상 문제인지 구분하기 위해 필요한 관측은 다음과 같습니다.

- VPN 연결 시에 발생하는 오류 메시지를 확인하여 문제의 원인을 파악합니다.
- 두 장비 간의 통신 패킷을 캡처하여 분석하여 VPN 연결의 성공 여부를 확인합니다.
- 관리 화면에서 VPN 연결 상태를 확인하고, 실제 데이터 통신이 가능함에도 불구하고 disable로 표시되는 경우, VPN 연결의 초기화 여부를 확인합니다.

5. 어느 쪽 설정을 먼저 변경해야 하는지 결정하기 전에 확보해야 할 근거는 다음과 같습니다.

- 두 장비 간의 VPN 연결 구성 정보를 확인하여 일치하는지 확인합니다.
- 두 장비 간의 통신 패킷을 캡처하여 분석하여 VPN 연결의 성공 여부를 확인합니다.
- 관리 화면에서 VPN 연결 상태를 확인하고, 실제 데이터 통신이 가능함에도 불구하고 disable로 표시되는 경우, VPN 연결의 초기화 여부를 확인합니다.

**NetScreen(ScreenOS) 명령어**

* `get vpn ipsec sa` : IPsec SA 목록을 확인합니다.
* `show vpn ipsec tunnel` : IPsec 터널 목록을 확인합니다.
* `get vpn ike policy` : IKE 정책 목록을 확인합니다.

* `get vpn ipsec sa` : IPsec SA 목록을 확인합니다.
* `show vpn ipsec tunnel` : IPsec 터널 목록을 확인합니다.
