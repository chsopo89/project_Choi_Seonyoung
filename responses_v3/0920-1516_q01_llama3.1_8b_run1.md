1. Phase 1과 Phase 2 중 어느 단계부터 확인해야 하는지?

Phase 1은 VPN 연결을 위한 암호화 키를 교환하는 단계입니다. Phase 2는 데이터 전송을 위한 세션을 설정하는 단계입니다. Phase 1 관련 down 로그가 반복적으로 발생하는 경우, 먼저 Phase 1 설정을 확인해 보아야 합니다.

2. 양쪽 FortiGate에서 서로 비교해야 하는 설정값은 무엇인지?

양쪽 FortiGate의 IPsec VPN 설정을 비교할 때 다음 설정값을 확인해야 합니다.

* Peer ID (Peer Identifier)
* Pre-shared key (PSK)
* IKE proposal
* IPSec proposal

이러한 설정값이 일치하지 않거나 잘못된 경우 Phase 1 연결이 실패할 수 있습니다.

3. 정상 통신이 가능한데도 down/up이 반복될 수 있는 원인 후보는 무엇인지?

정상적으로 통신이 가능하지만 down/up이 반복되는 경우에는 다음과 같은 원인이 있을 수 있습니다.

* 네트워크 환경의 변화로 인해 VPN 연결이 끊기는 현상
* FortiGate 장비의 성능 문제 또는 부하가 높아지는 경우
* IPsec VPN 프로토콜 자체의 버그 또는 취약점

4. 각 원인 후보를 어떤 관측 결과로 확인하거나 제외할 수 있는지?

네트워크 환경의 변화로 인한 VPN 연결 끊김 현상을 확인하기 위해서는 다음을 관찰해야 합니다.

* 네트워크 트래픽 분석을 통해 VPN 연결이 끊기고 다시 형성되는 패턴을 확인합니다.
* 네트워크 장비의 로그를 확인하여 VPN 연결이 끊기는 이유를 파악합니다.

FortiGate 장비의 성능 문제나 부하가 높아지는 경우에는 다음과 같은 관측 결과를 확인해야 합니다.

* FortiGate 장비의 CPU, 메모리 사용률을 확인합니다.
* 네트워크 트래픽 분석을 통해 VPN 연결이 끊기고 다시 형성되는 패턴을 확인합니다.

IPsec VPN 프로토콜 자체의 버그 또는 취약점은 Fortinet 공식 문서나 기술 지원 센터에서 제공하는 정보를 참고해야 합니다.

5. 설정 변경이 필요하다면 어떤 조건에서 어떤 종류의 설정을 변경해야 하는지?

Phase 1 관련 down 로그가 반복적으로 발생하는 경우, 먼저 Phase 1 설정을 확인하고 Peer ID, Pre-shared key, IKE proposal, IPSec proposal과 같은 설정값을 비교해 보아야 합니다. 만약 이러한 설정값이 일치하지 않거나 잘못된 경우에는 해당 설정값을 수정하여 재시도해야 합니다.

또한 네트워크 환경의 변화로 인한 VPN 연결 끊김 현상을 방지하기 위해서는 네트워크 트래픽 분석 및 장비 성능 모니터링을 통해 문제를 파악하고 해결해야 합니다.

정확한 명령어 또는 설정값은 FortiOS 7.6에서 실제 존재한다고 확신하지 못하므로 다음과 같이 제시합니다.

* `get system status` : 시스템 상태 확인
* `get vpn ipsec-esp proposal` : IPSec ESP 프로포osal 확인
* `get vpn ike proposal` : IKE 프로포osal 확인

위와 같은 명령어를 사용하여 Phase 1 관련 설정을 확인할 수 있습니다.
