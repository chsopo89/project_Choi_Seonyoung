Cisco Catalyst 스위치(IOS XE)와 Juniper 스위치(Junos OS) 사이의 트렁크 연결에서 일부 VLAN 통신 실패 및 루프성 트래픽 발생 문제를 해결하기 위해 아래와 같이 점검 순서와 방법을 제시합니다.

---

### 1) 트렁크 인터페이스에서 실제로 허용되거나 멤버로 포함된 VLAN 확인 방법

**Cisco IOS XE:**
```bash
show interfaces trunk
```
- 이 명령어는 트렁크 포트에 허용되는 VLAN 목록을 보여줍니다.  
- `allowed vlan` 또는 `members` 항목을 확인하여 해당 VLAN이 포함되어 있는지 확인해야 합니다.

**Junos OS:**
```bash
show interfaces ge-0/0/1 unit 0 family ethernet-switching
```
- `ethernet-switching-options` 하위의 `vlan` 설정을 확인합니다.
- `vlan members`를 통해 멤버 VLAN을 확인할 수 있습니다.

---

### 2) 문제가 발생하는 VLAN의 태깅 및 포트 멤버십 상태 확인 방법

**Cisco IOS XE:**
```bash
show vlan brief
```
- 이 명령어는 VLAN의 포트 멤버십 상태와 태깅 여부를 보여줍니다.  
- 특정 VLAN에 해당하는 포트가 `access` 또는 `trunk`로 설정되어 있는지 확인해야 합니다.

**Junos OS:**
```bash
show ethernet-switching table
```
- 이 명령어는 VLAN별로 포트의 MAC 주소 학습 상태와 연결된 VLAN을 보여줍니다.
- 특정 VLAN이 포트에 할당되었는지 확인합니다.

---

### 3) STP 상태 확인 및 루프 관련 포트 판단

**Cisco IOS XE:**
```bash
show spanning-tree interface <interface> detail
```
- 이 명령어는 포트의 STP 상태(예: forwarding, blocking 등)를 보여줍니다.  
- `blocked` 또는 `listening` 상태인 포트가 루프 발생 가능성이 있습니다.

**Junos OS:**
```bash
show spanning-tree interface ge-0/0/1 detail
```
- Junos에서 STP 상태도 동일하게 확인할 수 있으며, `blocked` 상태의 포트가 루프 원인이 될 수 있습니다.

---

### 4) MAC 주소 학습 상태로 L2 전달 경로 확인

**Cisco IOS XE:**
```bash
show mac address-table
```
- 이 명령어는 특정 VLAN에 해당하는 MAC 주소와 연결된 포트를 보여줍니다.  
- 문제 VLAN의 MAC 주소가 어느 포트에 할당되었는지 확인하여 전달 경로를 파악합니다.

**Junos OS:**
```bash
show ethernet-switching table
```
- Junos에서 MAC 주소 학습 상태도 동일하게 확인할 수 있으며, 특정 VLAN의 MAC 주소 분포를 확인해야 합니다.

---

### 5) 링크 up 및 LLDP 인식과 VLAN 트래픽 전달 성공을 구분해야 하는 이유

- **링크 up 및 LLDP 인식**: 이는 물리적 연결이 정상인지 여부를 나타내며, VLAN 설정과 무관한 단순한 네트워크 상태입니다.  
- **VLAN 트래픽 전달 성공**: 이는 VLAN 구성, 포트 멤버십, 태깅 등이 모두 정확하게 설정되어야 통신이 가능합니다.  
- 두 상태가 동일하지 않다면, VLAN 설정 오류나 포트 구성 문제로 인해 발생할 수 있습니다.

---

### 6) Cisco IOS XE와 Junos OS 명령어 구분

- 위에서 제시한 명령어는 각 벤더의 OS에 따라 다르게 작동할 수 있으므로, 반드시 해당 장비의 문서를 참고해야 합니다.
- 예: `show interfaces trunk`은 Cisco에서만 사용 가능하며, Junos에서는 `show interfaces ge-0/0/1 unit 0 family ethernet-switching`을 사용합니다.

---

### 7) 한쪽 벤더의 기능을 다른 벤더에도 동일하게 적용하지 않음

- Cisco와 Junos는 서로 다른 CLI 구조와 설정 방식을 가집니다.  
- 예: VLAN 구성 시 `vlan <id>` 명령어는 Cisco에서 사용되며, Junos에서는 `vlan <id>`도 사용 가능하나, 포트 할당 방식이 다릅니다.
- 따라서 각 벤더의 명령어를 별도로 확인해야 합니다.

---

### 8) 설정 변경 전에 현재 상태 확인 및 백업 항목

- **Cisco IOS XE**:  
  - `show running-config` 또는 `copy running-config startup-config`로 설정을 백업합니다.  
  - `show vlan brief`, `show interfaces trunk`, `show spanning-tree` 등을 통해 현재 상태를 기록합니다.

- **Junos OS**:  
  - `show configuration`으로 설정을 확인하고, `save` 명령어로 설정을 저장합니다.  
  - `show ethernet-switching table`, `show spanning-tree interface` 등을 통해 상태를 기록합니다.

---

### 9) 루프 위험 최소화하면서 단계적 트래픽 이전 순서

1. **VLAN 구성 및 포트 멤버십 확인** →  
2. **STP 상태 점검 및 루프 방지 설정 적용** →  
3. **MAC 주소 학습 상태 확인 및 전달 경로 파악** →  
4. **트래픽 이전 시 VLAN별로 분리하여 진행** →  
5. **모든 VLAN이 정상 통신 후, 전체 네트워크로 이전**

---

### 10) 문제 발생 시 다음 단계 진행 여부 판단 기준

- **문제가 발생하면**:  
  - 현재 설정을 복원하고, 이전 단계로 돌아가서 다시 점검해야 합니다.  
  - 루프 발생 시는 STP 상태를 우선적으로 확인하고, 포트 상태를 변경합니다.

- **문제가 해결되면**:  
  - 다음 단계로 진행하며, 모든 VLAN에 대해 동일한 절차를 반복합니다.

---

**참고:** 명령어의 정확성은 장비 모델 및 OS 버전에 따라 달라질 수 있으므로, 각 벤더의 공식 문서나 CLI 명령어 목록을 반드시 참고해야 합니다.
