1. 실제 패킷이 어느 정책에 매칭되는지 확인하는 방법:

   - `diag firewall packet-trace` 명령어를 사용하여 특정 트래픽의 패킷 경로를 추적할 수 있습니다. 이 명령어는 트래픽의 패킷 경로를 보여주며, 각 정책에서 패킷이 어떻게 처리되는지 확인할 수 있습니다.

2. 해당 정책의 source/destination/interface/service 등 매칭 조건 중 무엇을 비교해야 하는지:

   - FortiGate 방화벽 정책은 Source, Destination, Service, Interface, Action 등 다양한 매칭 조건을 지원합니다. 정책에 입력한 매칭 조건이 정확하게 맞는지 확인해야 합니다.
   - 예를 들어, Source IP 주소가 192.168.1.100 인 경우, `srcaddr` 옵션을 사용하여 192.168.1.100 이라는 IP 주소를 직접 입력하거나, `srcaddr` 옵션에 `any` 또는 `all` 을 입력하여 모든 출발지 IP 주소를 허용할 수 있습니다.

3. 정책의 순서가 높아도 매칭되지 않을 수 있는 조건:

   - FortiGate 방화벽 정책은 Top-down 방식으로 운영되며, 정책의 순서는 중요합니다. 그러나 정책의 순서만으로는 트래픽이 매칭되는지 여부를 결정할 수 없습니다.
   - 예를 들어, 정책 A 에서 Source IP 주소가 192.168.1.100 인 경우, 정책 B 에서 Destination IP 주소가 192.168.1.100 인 경우, 정책 A 가 먼저 적용될 수 있지만, 정책 B 가 더 높은 우선순위를 가지고 있다면, 정책 B 가 적용될 수 있습니다.

4. 정책 자체가 평가 대상에서 제외되거나 기대와 다른 방식으로 처리되는 경우 무엇을 확인해야 하는지:

   - 정책의 Action 옵션을 확인하여 트래픽이 허용되거나 차단되는지 여부를 확인할 수 있습니다.
   - 예를 들어, 정책에 `allow` 옵션이 설정되어 있는 경우, 트래픽은 허용됩니다. 그러나 정책에 `deny` 옵션이 설정되어 있는 경우, 트래픽은 차단됩니다.

5. 관측 결과에 따라 설정 변경 전에 어떤 사실을 먼저 확정해야 하는지:

   - FortiGate 방화벽 정책의 순서와 매칭 조건이 정확하게 맞는지 확인해야 합니다.
   - 정책의 Action 옵션과 우선순위가 올바르게 설정되었는지 확인해야 합니다.
   - 트래픽 패턴이 정책에 어떻게 매칭되는지 확인해야 합니다.

정확한 명령어를 확신하지 못하는 경우, 확인이 필요하다고 명시합니다.
