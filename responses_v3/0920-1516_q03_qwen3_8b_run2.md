1) **FortiGate에서 로그 이벤트 자체가 생성되고 있는지**  
   - 점검 순서: 먼저, FortiGate에서 실제로 로그 이벤트가 발생하고 있는지 확인해야 합니다. 예를 들어, 방화벽 정책을 통해 트래픽이 통과되거나 차단되는 경우, 해당 이벤트는 로그로 기록됩니다.  
   - 사용할 수 있는 명령어: `diagnose log filter` 또는 `get system event`  
     - `diagnose log filter <log-type>` (예: `diagnose log filter firewall`)  
       - 특정 로그 유형(예: 방화벽, 인증, 시스템 등)에 대한 이벤트를 필터링하여 확인합니다.  
     - `get system event`  
       - 최근 발생한 시스템 이벤트 목록을 보여줍니다.  
   - 주의사항: 명확한 로그 유형이 필요하며, 정확한 문법은 FortiOS 7.6에서 검증되지 않았으므로, 명령어 사용 전 정확한 문법 확인이 필요합니다.

2) **생성된 로그가 로컬 저장 또는 메모리 처리 단계까지 도달하는지**  
   - 점검 순서: 로그 이벤트가 생성되었지만 로컬에 저장되지 않는 경우, 로컬 저장 설정이나 메모리 처리 문제일 수 있습니다.  
   - 사용할 수 있는 명령어: `get log memory`  
     - 로그 메모리 상태를 확인합니다.  
   - 주의사항: 로그 저장 경로나 용량 제한 설정도 확인해야 합니다. 예를 들어, `config log memory`에서 설정이 정상인지 점검해야 합니다.

3) **외부 로그 서버로 전송을 시도하고 있는지**  
   - 점
   - 사용할 수 있는 명령어: `diagnose log config`  
     - 로그 전송 구성 정보를 확인합니다.  
   - 주의사항: 외부 로그 서버에 대한 설정(예: IP, 포트, 프로토콜 등)이 올바르게 입력되었는지 확인해야 합니다.

4) **FortiGate에서 실제 로그 패킷이 송신되는지**  
   - 점검 순서: 로그가 생성되고, 로컬 저장까지 도달했지만 외부 서버로 전송되지 않는 경우, 로그 패킷이 실제로 전송되는지 확인해야 합니다.  
   - 사용할 수 있는 명령어: `diagnose log monitor`  
     - 실시간으로 로그 패킷이 전송되는지 모니터링합니다.  
   - 주의사항: 이 명령어는 임시적으로 사용되며, 정확한 문법은 FortiOS 7.6에서 검증되지 않았으므로, 명령어 사용 전 정확한 문법 확인이 필요합니다.

5) **로그 서버가 해당 패킷을 실제로 수신하는지**  
   - 점검 순서: 로그 패킷이 FortiGate에서 전송되었지만 로그 서버에 도달하지 않는 경우, 네트워크 문제나 서버 설정 문제일 수 있습니다.  
   - 사용할 수 있는 명령어: 로그 서버 측에서 `tcpdump` 또는 `Wireshark`를 사용하여 패킷 수신 여부 확인  
     - 예: `tcpdump -i eth0 port 514` (UDP/514 또는 TCP/514)  
   - 주의사항: 로그 서버가 UDP/TCP 기반으로 수신하는지 확인해야 하며, 포트 번호도 확인해야 합니다.

6) **각 단계의 결과에 따라 문제를 생성·저장·전송·수신 중 어느 구간으로 좁힐 수 있는지**  
   - 점검 순서: 위 단계에서 문제가 발생한 구간을 파악하여 원인을 추적합니다.  
     - 예: 로그 이벤트가 생성되지 않으면, 방화벽 정책이나 시스템 이벤트 설정 문제일 수 있습니다.  
     - 로그가 로컬 저장되지 않는 경우, 메모리 설정 또는 저장 경로 문제일 수 있습니다.  
     - 전송이 실패하는 경우, 로그 서버 구성, 네트워크 설정, 포트/프로토콜 문제일 수 있습니다.  
     - 패킷이 전송되었지만 서버에 도달하지 않는 경우, 네트워크 장애나 서버 설정 문제일 수 있습니다.

- **요약**: 위 단계를 따라 점검하면, 로그 생성 → 저장 → 전송 → 수신까지의 과정에서 문제가 발생하는 구간을 확인할 수 있습니다. 각 단계별 명령어는 FortiOS 7.6에서 사용 가능할 수도 있으므로, 정확한 문법과 존재 여부를 확인해야 합니다. 재부팅이나 초기화 등의 영향이 큰 조치는 원인 파악 전에는 권장되지 않습니다.
