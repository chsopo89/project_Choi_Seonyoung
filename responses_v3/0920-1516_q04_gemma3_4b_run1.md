## FortiGate(FortiOS 7.6) 방화벽 정책 매칭 문제 해결 가이드

네트워크 엔지니어로서 FortiGate 방화벽 정책 문제 해결을 위한 단계별 접근법과 점검 사항을 제시합니다. FortiOS 7.6 환경에서 Top-down 방식으로 정책을 운영하고 있으며, 특정 트래픽이 예상 정책에 매치되지 않고 다음 정책부터 적용되는 현상을 진단하고 해결하는 데 초점을 맞추겠습니다.

**1) 실제 패킷이 어느 정책에 매칭되는지 확인하는 방법**

문제 해결의 첫 번째 단계는 실제로 패킷이 어떤 정책에 매치되는지 정확하게 파악하는 것입니다. 이를 위해 다음과 같은 방법을 활용할 수 있습니다.

* **FortiGate Analyzer:** FortiAnalyzer는 방화벽 로그를 분석하여 정책 매칭 결과를 시각적으로 보여줍니다.  정책별 허용/차단 통계를 제공하며, 문제 발생 트래픽을 특정 정책과 연관시켜 빠르게 식별할 수 있습니다. (FortiOS 7.6에서 Analyzer 사용 가능 여부 확인 필요)
* **Packet Capture & Analysis (Wireshark 등):** Wireshark와 같은 네트워크 패킷 분석 도구를 사용하여 실제 네트워크 트래픽을 캡처하고 분석합니다.  패킷 헤더 정보(소스 IP, 목적지 IP, 포트 번호 등)를 검토하여 어떤 정책이 적용되었는지 확인할 수 있습니다.  정책 매칭 과정에서 발생하는 오류나 예상치 못한 동작을 파악하는 데 유용합니다.
* **FortiGate CLI (Command Line Interface) - `show policy match`:** FortiOS CLI를 통해 특정 IP 주소 또는 포트 번호를 대상으로 하는 패킷이 어떤 정책에 매치되는지 확인하는 명령어를 사용할 수 있습니다. 정확한 명령어 확인이 필요합니다.

**2) 해당 정책의 source/destination/interface/service 등 매칭 조건 중 무엇을 비교해야 하는지**

방화벽 정책은 다양한 매칭 조건을 기반으로 작동합니다. 다음은 주요 매칭 조건과 비교 시 고려 사항입니다.

* **Source IP Address:** 소스 IP 주소가 정책에 명시적으로 정의되어 있는지, 또는 와일드카드(*)를 사용하여 모든 IP 주소를 허용하는지 확인합니다.
* **Destination IP Address:** 목적지 IP 주소 역시 정책에 명시적으로 정의되어 있는지, 와일드카드(*)를 사용하는지 확인합니다.
* **Interface:** 트래픽이 들어오는 인터페이스와 정책에서 지정된 인터페이스가 일치하는지 확인합니다.  정책이 특정 인터페이스(예: WAN)에서만 적용되도록 설정되었을 수 있습니다.
* **Service / Port:** 포트 번호는 정책의 핵심 매칭 조건입니다. 정책에서 허용되는 서비스(예: HTTP, HTTPS) 또는 특정 포트 번호를 명시적으로 지정했는지 확인합니다.  포트 범위 (예: 80-85)를 사용한 경우, 해당 범위 내의 모든 포트가 허용되는지 검토해야 합니다.
* **Protocol:** TCP, UDP 등 프로토콜 유형도 정책 매칭에 영향을 미칩니다.

**3) 정책의 순서가 높아도 매칭되지 않을 수 있는 조건은 무엇인지**

정책 순서는 중요하지만, 다음 조건에서는 정책의 순서가 높아도 트래픽이 매치되지 않을 수 있습니다.

* **Implicit Deny:** FortiOS에서 기본적으로 모든 트래픽을 차단하는 "Implicit Deny" 설정이 활성화되어 있는지 확인합니다.  만약 Implicit Deny가 활성화되어 있다면, 명시적으로 허용된 정책 이후의 트래픽은 모두 차단됩니다.
* **Policy Order Conflicts:** 여러 정책이 동일한 IP 주소 또는 포트 번호에 대해 서로 다른 규칙을 가지고 있을 경우, FortiGate는 일반적으로 가장 먼저 일치하는 정책을 적용합니다.  정책 순서를 변경해도 충돌하는 정책이 존재한다면 문제가 해결되지 않습니다.
* **Log-Based Policy:** 로그 기반 정책(Log Matching)을 사용하고 있는 경우, 로그 패턴과 트래픽 패턴이 일치해야 정책이 적용됩니다.

**4) 정책 자체가 평가 대상에서 제외되거나 기대와 다른 방식으로 처리되는 경우 무엇을 확인해야 하는지**

정책 자체가 평가 대상에서 제외되거나 예상과 다른 방식으로 처리되는 경우 다음 사항을 확인해야 합니다.

* **Policy Status:** 정책의 상태가 "Enabled"로 설정되어 있는지 확인합니다.  정책이 비활성화된 상태라면 당연히 적용되지 않습니다.
* **Rule Type:** 정책의 Rule Type (예: Destination MAC Filter, Source Address List)이 올바르게 설정되었는지 확인합니다.
* **Advanced Features:** 정책에 Advanced Features (예: QoS, IPS)가 적용되어 있다면, 해당 기능들이 정책 매칭에 영향을 미칠 수 있습니다.  각 기능의 설정을 검토하여 의도하지 않은 동작이 발생하고 있지 않은지 확인합니다.
* **Security Profiles:** Security Profile이 활성화되어 있다면, 해당 프로필의 규칙들이 정책 매칭에 영향을 줄 수 있습니다.

**5) 관측 결과에 따라 설정 변경 전에 어떤 사실을 먼저 확정해야 하는지**

문제 해결을 위해 설정 변경 전에 다음 사항을 먼저 확정하는 것이 중요합니다.

1. **트래픽의 정확한 특성 파악:** 트래픽의 소스/목적지 IP 주소, 목적지 포트 번호, 프로토콜 유형 등을 정확하게 파악합니다.  Wireshark를 사용하여 패킷 내용을 분석하면 더욱 정확한 정보를 얻을 수 있습니다.
2. **정책의 의도된 동작 확인:** 해당 정책이 어떤 트래픽을 허용하기 위한 것인지 명확하게 이해합니다.  정책의 목적과 현재 발생하고 있는 문제를 비교하여 문제의 근본 원인을 파악합니다.
3. **FortiGate 설정의 일관성 검토:** FortiOS 버전, 인터페이스 설정, 보안 프로필 설정 등 FortiGate 전체 설정의 일관성을 검토합니다.  설정 오류는 예상치 못한 정책 매칭 결과를 초래할 수 있습니다.

**주의사항:**

* 위 내용은 일반적인 지침이며, 실제 환경에 따라 다를 수 있습니다.
* FortiOS 7.6의 정확한 명령어 문법은 공식 문서 또는 지원 자료를 참조해야 합니다.
* 문제 해결 과정에서 발생하는 모든 로그 및 설정을 기록하여 추후 분석에 활용합니다.

**추가적으로 필요한 정보:**

* FortiGate 모델명 및 FortiOS 버전 (예: FG-380A, FortiOS 7.6)
* 해당 정책이 적용된 인터페이스 (예: WAN, LAN)
* 문제 발생 시점의 트래픽 패턴 (예: 특정 시간대에만 발생하는 트래픽)
* 관련 로그 파일 (예: 방화벽 로그, 시스템 로그)

위 정보를 바탕으로 더욱 정확하고 상세한 진단과 해결책을 제시할 수 있습니다.
