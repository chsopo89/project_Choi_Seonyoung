1) **외부 클라이언트의 요청이 FortiGate까지 도착하는지 확인하는 방법**  
   - 외부에서 VIP에 대한 트래픽이 도달하는지 확인하기 위해 `diagnose sys session list` 명령어를 사용하여 세션 목록을 확인합니다. 이 명령어는 현재 활성화된 세션 정보를 보여주며, 외부 클라이언트가 VIP로 접근했는지를 확인할 수 있습니다.  
   - 또한, `diag debug flow enable` 명령어를 통해 흐름 디버깅을 활성화하고, `tcpdump` 또는 `diag debug flow show`를 이용해 패킷 흐름을 추적할 수도 있습니다.  
   - **관측 결과**: 세션이 생성되지 않거나, 패킷이 도달하지 않는다면, 네트워크 장애나 라우팅 문제, 방화벽 정책의 설정 오류 등이 있을 수 있습니다.

2) **FortiGate가 해당 요청을 올바른 VIP와 정책에 매칭하는지 확인하는 방법**  
   - `diagnose firewall session list` 명령어로 세션 정보를 확인하여, 요청이 어떤 VIP와 정책에 매칭되는지를 확인합니다.  
   - `get system interface` 명령어로 VIP가 속한 인터페이스를 확인하고, 해당 인터페이스에서 트래픽이 처리되고 있는지 확인합니다.  
   - **관측 결과**: 요청이 VIP와 정책에 매칭되지 않거나, 잘못된 정책이 적용된다면, 정책의 설정 오류나 VIP 구성 문제일 수 있습니다.

3) **VIP 변환 이후 웹 서버 방향으로 패킷이 전달되는지 확인하는 방법**  
   - `diagnose firewall session list` 명령어로 세션 상태를 확인하여, 패킷이 웹 서버로 전달되고 있는지를 확인합니다.  
   - `tcpdump` 또는 `diag debug flow show`를 사용해 패킷 흐름을 추적할 수도 있습니다.  
   - **관측 결과**: 패킷이 전달되지 않는다면, VIP 변환 설정에 문제가 있거나, 정책에서 목적지 IP가 잘못 지정된 경우입니다.

4) **웹 서버의 응답 패킷이 어떤 경로로 돌아오는지 확인해야 하는 이유**  
   - 외부 클라이언트는 요청을 FortiGate로 보내고, FortiGate는 웹 서버로 전달한 후, 웹 서버는 응답을 보냅니다. 이 응답 패킷은 원래 경로를 따라 다시 클라이언트에게 도달해야 합니다.  
   - 만약 응답 패킷이 올바르게 돌아오지 않는다면, 라우팅 설정, NAT 구성, 또는 방화벽 정책에서의 허용 규칙 등에 문제가 있을 수 있습니다.

5) **각 단계의 관측 결과에 따라 다음 점검 위치를 어떻게 결정할지**  
   - 첫 번째 단계에서 요청이 FortiGate에 도착하지 않으면, 네트워크 장애나 라우팅 문제를 먼저 확인합니다.  
   - 두 번째 단계에서 요청이 VIP와 정책에 매칭되지 않거나 잘못된 정책이 적용되면, 정책 및 VIP 설정을 다시 검토합니다.  
   - 세 번째 단계에서 패킷 전달이 실패하면, VIP 변환 설정과 정책에서 목적지 IP가 올바르게 지정되었는지를 점검합니다.  
   - 네 번째 단계에서 응답 패킷이 돌아오지 않는다면, 라우팅 설정, NAT 구성, 또는 방화벽 정책에서의 허용 규칙 등을 확인해야 합니다.  
   - 각 단계에서 관측 결과를 바탕으로 문제 구간을 좁히고, 필요한 경우 `diagnose` 명령어나 `tcpdump`를 사용해 세부적인 트래픽 분석을 수행합니다.  
   - 이미 정상이라고 제시된 항목은 재설정하지 않고, 관측을 통해 문제 구간을 점진적으로 줄이는 방식으로 점검을 진행합니다.
