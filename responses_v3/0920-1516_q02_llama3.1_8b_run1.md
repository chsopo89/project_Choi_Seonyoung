1.  외부 클라이언트의 요청이 FortiGate까지 도착하는지 확인하는 방법
    *   **arp-scan** 명령어를 사용하여 네트워크 내에 있는 장비 목록을 확인할 수 있습니다. 이 명령어를 사용하여 VIP가 할당된 인터페이스에 연결된 장비가 있는지 확인합니다.
        ```
        # arp-scan -I <인터페이스 이름> -r <VIP IP>
        ```
    *   또는, **tcpdump** 명령어를 사용하여 VIP로 들어오는 패킷을 캡처해 볼 수 있습니다. 이 명령어를 사용하여 외부 클라이언트의 요청이 FortiGate까지 도착하는지 확인합니다.

2.  FortiGate가 해당 요청을 올바른 VIP와 정책에 매칭하는지 확인하는 방법
    *   **diag sniffer packet** 명령어를 사용하여 VIP로 들어오는 패킷을 캡처해 볼 수 있습니다. 이 명령어를 사용하여 FortiGate가 해당 요청을 올바른 VIP와 정책에 매칭하는지 확인합니다.
        ```
        # diag sniffer packet any 'ip.src == <VIP IP>' -S -c 10
        ```
    *   또는, **get policy id** 명령어를 사용하여 현재 활성화된 정책 ID를 확인할 수 있습니다. 이 명령어를 사용하여 현재 활성화된 정책이 올바른 정책인지 확인합니다.

3.  VIP 변환 이후 웹 서버 방향으로 패킷이 전달되는지 확인하는 방법
    *   **diag sniffer packet** 명령어를 사용하여 VIP로 들어오는 패킷을 캡처해 볼 수 있습니다. 이 명령어를 사용하여 VIP 변환 이후 웹 서버 방향으로 패킷이 전달되는지 확인합니다.
        ```
        # diag sniffer packet any 'ip.src == <VIP IP>' -S -c 10
        ```
    *   또는, **get session** 명령어를 사용하여 현재 활성화된 세션 정보를 확인할 수 있습니다. 이 명령어를 사용하여 현재 활성화된 세션이 올바른 세션인지 확인합니다.

4.  웹 서버의 응답 패킷이 어떤 경로로 돌아오는지 확인해야 하는 이유
    *   외부 클라이언트가 VIP를 통해 웹 서비스에 접속하면, FortiGate는 요청을 받고 VIP 변환 후 웹 서버로 패킷을 전달합니다. 그러나 웹 서버의 응답 패킷은 다시 FortiGate를 거쳐서 외부 클라이언트에게 전달됩니다. 따라서, 웹 서버의 응답 패킷이 어떤 경로로 돌아오는지 확인해야 합니다.

5.  각 단계의 관측 결과에 따라 다음 점검 위치를 결정하는 방법
    *   **arp-scan** 명령어를 사용하여 네트워크 내에 있는 장비 목록을 확인한 결과, VIP가 할당된 인터페이스에 연결된 장비가 없다면, 다음으로는 **diag sniffer packet** 명령어를 사용하여 VIP로 들어오는 패킷을 캡처해 볼 수 있습니다.
    *   또는, **get policy id** 명령어를 사용하여 현재 활성화된 정책 ID를 확인한 결과, 현재 활성화된 정책이 올바른 정책이 아니라면, 다음으로는 **get session** 명령어를 사용하여 현재 활성화된 세션 정보를 확인할 수 있습니다.
