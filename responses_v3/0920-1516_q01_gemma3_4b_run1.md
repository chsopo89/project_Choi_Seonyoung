## FortiGate IPsec VPN Phase Down/Up 문제 진단 및 해결 방안 (FortiOS 7.6)

**개요:** FortiGate 두 대 사이에 구성된 IPsec VPN 연결에서 Phase 1 및 Phase 2 관련 down/up 로그가 반복적으로 발생하며 연결 상태가 끊겼다가 다시 형성되는 현상이 관측되고 있습니다. 단순 재설정을 넘어 문제의 근본적인 원인을 파악하고, 각 단계별 점검 사항과 해결 방안을 제시합니다.

**1. 문제 단계별 우선순위: Phase 2부터 시작**

일반적으로 IPsec VPN 문제 발생 시 Phase 2 설정 오류가 Phase 1 설정 오류를 유발하는 경우가 많습니다. 따라서 초기 진단은 **Phase 2 설정**부터 시작하여 문제를 좁혀나가는 것이 효율적입니다. Phase 1 설정도 최종적으로 Phase 2에 영향을 미칠 수 있으므로, Phase 2 문제 해결 후 Phase 1 설정을 검토해야 합니다.

**2. 비교 대상 설정값:**

다음은 FortiGate 두 대에서 비교해야 하는 주요 설정값입니다. (FortiOS 7.6 기준)

*   **Phase 1:**
    *   프록시 ID (Proxy ID)
    *   프록시 본명 (Proxy Name)
    *   프록시 유형 (Proxy Type - IKEv1/IKEv2)
    *   프록시 인증 방법 (Authentication Method - Pre-shared Key, Certificate 등)
    *   프록시 키 (Pre-shared Key) 또는 인증서 (Certificate)
    *   IKE 보안 정책 (IKE Security Policy - Hash Algorithm, Diffie-Hellman Group, Encryption Algorithm 등)
*   **Phase 2:**
    *   VPN 터널 이름 (VPN Tunnel Name)
    *   IPsec 보안 정책 (IPsec Security Policy - ESP Protocol, SA Lifetime, PFS Group, Hash Algorithm, Encryption Algorithm 등)
    *   Local Network/Remote Network 설정 (각 FortiGate의 네트워크 범위 정의)
    *   NAT Traversal 설정 (NAT-T 활성화 여부 및 관련 설정)

**3. 정상 통신 가능한데도 down/up이 반복될 수 있는 원인 후보:**

*   **IKE 보안 정책 불일치:** Phase 1 및 Phase 2 IKE 보안 정책 간의 불일치는 연결 실패의 주요 원인입니다. 특히 Diffie-Hellman 그룹, 해시 알고리즘, 암호화 알고리즘 등의 차이가 발생하면 인증 과정에서 오류가 발생하여 down 상태로 전환될 수 있습니다.
*   **SA Lifetime 설정 문제:** SA Lifetime는 IPsec Security Association의 생명 주기를 결정합니다. 너무 짧게 설정하면 연결 끊김이 빈번하게 발생할 수 있으며, 너무 길게 설정하면 보안상의 취약점이 발생할 수 있습니다.
*   **NAT Traversal (NAT-T) 관련 문제:** NAT 환경에서 IPsec VPN을 사용할 경우 NAT-T 설정을 통해 NAT 장비에 IPsec 트래픽을 전달해야 합니다. NAT-T 설정 오류 또는 NAT 장비와의 호환성 문제는 연결 실패를 유발할 수 있습니다.
*   **CPU/메모리 과부하:** FortiGate의 CPU 또는 메모리가 과도하게 사용되면 IPsec 프로세스가 제대로 작동하지 않아 down 상태로 전환될 수 있습니다.
*   **패킷 손실 및 재전송:** 네트워크 구간에서 패킷 손실이 발생하고, 해당 패킷이 재전송되는 경우 IPsec SA가 갱신되지 않아 연결이 끊어질 수 있습니다.
*   **방화벽 규칙 충돌:** VPN 트래픽을 허용하는 방화벽 규칙과 다른 트래픽을 차단하는 방화벽 규칙 간의 충돌이 발생할 수 있습니다.

**4. 원인 후보 확인/제외 관측 결과:**

| 원인 후보             | 확인 방법                                                                                               | 제외 방법                                                                                              |
| :------------------- | :----------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------- |
| IKE 보안 정책 불일치 | `show system ikev1` (IKEv1), `show system ikev2` (IKEv2) 명령어를 통해 Phase 1 및 Phase 2 설정 비교, 로그 분석 (IKE 관련 오류 메시지 확인) | 동일한 IKE 보안 정책 설정 확인, IKE 버전 호환성 확인                                                     |
| SA Lifetime 문제     | `show system ipsec sa` 명령어 통해 SA Lifetime 값 확인, 네트워크 지연 시간 고려하여 적절한 값 설정, 테스트 환경에서 SA Lifetime 변경 후 영향 확인 |  SA Lifetime가 너무 짧거나 길게 설정되지 않았는지 확인                                                    |
| NAT Traversal 문제   | `show system ipsec nat` 명령어 통해 NAT-T 설정 확인, NAT 장비와의 통신 테스트, NAT-T 관련 로그 분석             | NAT-T 활성화 여부 및 관련 설정이 올바르게 구성되었는지 확인                                               |
| CPU/메모리 과부하    | `show resource` 명령어 통해 CPU 및 메모리 사용량 모니터링, 프로세스별 자원 사용량 분석                         | 불필요한 프로세스 종료, 시스템 성능 향상                                                               |
| 패킷 손실/재전송     | 네트워크 구간 트래픽 캡처 (Wireshark 등)를 통해 패킷 손실 및 재전송 현황 분석, 네트워크 장비 상태 점검       | 네트워크 장비의 링크 상태, 대역폭, 오류율 등을 확인                                                     |
| 방화벽 규칙 충돌      | 방화벽 규칙 목록 확인 (`show firewall log`) 및 필터링 규칙 검토, VPN 트래픽을 허용하는 규칙과 다른 트래픽을 차단하는 규칙 비교 |  VPN 트래픽을 허용하는 규칙이 올바르게 구성되었는지 확인                                                 |

**5. 설정 변경 조건 및 종류:**

*   **IKE 보안 정책 불일치 시:** Phase 1 및 Phase 2 IKE 보안 정책을 동일하게 설정합니다. (Diffie-Hellman 그룹, 해시 알고리즘, 암호화 알고리즘 등)
*   **SA Lifetime 문제 시:** 네트워크 지연 시간을 고려하여 적절한 SA Lifetime 값을 설정합니다. 일반적으로 30초 ~ 1분 사이의 값을 사용하며, 테스트 환경에서 다양한 값으로 설정하여 영향을 확인합니다.
*   **NAT Traversal 문제 시:** NAT-T 설정을 활성화하고, NAT 장비와의 호환성을 확인합니다. 필요에 따라 NAT-T 관련 로그를 분석하여 문제를 진단합니다.
*   **CPU/메모리 과부하 시:** 불필요한 프로세스를 종료하거나 시스템 성능을 향상시킵니다.
*   **패킷 손실/재전송 문제 시:** 네트워크 구간의 링크 상태, 대역폭, 오류율 등을 점검하고, 필요한 경우 네트워크 장비를 교체하거나 업그레이드합니다.
*   **방화벽 규칙 충돌 시:** VPN 트래픽을 허용하는 방화벽 규칙과 다른 트래픽을
