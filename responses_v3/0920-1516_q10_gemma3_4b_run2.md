## Cisco Catalyst (IOS XE) - Juniper SRX (Junos OS) 스위치 간 VLAN 통신 문제 진단 및 해결

**전제:**

*   Cisco Catalyst 스위치는 IOS XE 버전 정보가 불명확하므로 일반적인 지침을 제공합니다.
*   Juniper SRX 스위치는 Junos OS 버전 정보가 불명확하므로 일반적인 지침을 제공합니다.
*   트렁크 인터페이스는 IEEE 802.1Q로 구성되어 있으며, VLAN ID는 동일합니다.
*   물리 링크는 Up이며 LLDP를 통해 서로 이웃으로 인식됩니다.
*   문제는 특정 VLAN만 통신되지 않고, 간헐적으로 루프성 트래픽이 발생한다는 점입니다.

**점검 순서 및 내용:**

**1) 트렁크 인터페이스에서 실제로 허용되거나 멤버로 포함된 VLAN을 확인하는 방법 (Cisco & Juniper)**

*   **Cisco IOS XE:** `show VLAN brief` 명령어를 사용하여 트렁크 인터페이스에 설정된 VLAN 목록을 확인합니다. 또한, `show interface <트렁크 인터페이스> campaign` 명령어를 통해 해당 인터페이스의 트렁크 캠페인 구성(member VLAN)을 확인합니다.
    *   `show VLAN brief`: VLAN ID, 이름, 상태 등을 보여줍니다.
    *   `show interface <트렁크 인터페이스> campaign`: 트렁크 캠페인 구성 정보를 보여줍니다.
*   **Juniper SRX Junos OS:** `show configuration interfaces <트렁크 인터페이스> vlan` 명령어를 사용하여 트렁크 인터페이스에 설정된 VLAN 목록을 확인합니다.  `show configuration interfaces <트렁크 인터페이스>` 명령어를 통해 인터페이스 전체 설정 및 VLAN 멤버십 정보를 확인할 수 있습니다.
    *   `show configuration interfaces <트렁크 인터페이스> vlan`: 트렁크 인터페이스의 VLAN 멤버십 설정을 보여줍니다.
    *   `show configuration interfaces <트렁크 인터페이스>`: 인터페이스 전체 설정 및 VLAN 멤버십 정보를 보여줍니다.

**2) 문제가 발생하는 VLAN의 태깅 및 포트 멤버십 상태를 확인하는 방법 (Cisco & Juniper)**

*   **Cisco IOS XE:** `show interface <포트> campaign` 명령어를 사용하여 해당 포트가 어떤 VLAN에 속해 있는지 확인합니다. 또한, `show mac address-table interface <포트>` 명령어를 통해 MAC 주소 학습 상태를 확인하고, VLAN에 해당하는 MAC 주소가 올바르게 학습되었는지 검증합니다.
    *   `show interface <포트> campaign`: 해당 포트의 캠페인 구성(VLAN 멤버십)을 보여줍니다.
    *   `show mac address-table interface <포트>`: 해당 포트에서 학습된 MAC 주소 테이블을 보여줍니다.
*   **Juniper SRX Junos OS:** `show configuration interfaces <포트> vlan` 명령어를 사용하여 해당 포트가 어떤 VLAN에 속해 있는지 확인합니다.  `show configuration interfaces <포트>` 명령어를 통해 인터페이스 전체 설정 및 VLAN 멤버십 정보를 확인할 수 있습니다. 또한, `show mac address-table interface <포트>` 명령어를 통해 MAC 주소 학습 상태를 확인하고, VLAN에 해당하는 MAC 주소가 올바르게 학습되었는지 검증합니다.
    *   `show configuration interfaces <포트> vlan`: 해당 포트의 VLAN 멤버십 설정을 보여줍니다.
    *   `show configuration interfaces <포트>`: 인터페이스 전체 설정 및 VLAN 멤버십 정보를 보여줍니다.
    *   `show mac address-table interface <포트>`: 해당 포트에서 학습된 MAC 주소 테이블을 보여줍니다.

**3) STP 상태를 확인하여 새로 연결한 포트가 루프와 관련 있는지 판단하는 방법 (Cisco & Juniper)**

*   **Cisco IOS XE:** `show spanning-tree statistics` 명령어를 사용하여 STP 통계를 확인합니다. 특히, 새로 연결된 포트의 BPDU count, forward/forward delay 등을 확인하여 루프 발생 가능성을 평가합니다.
    *   `show spanning-tree statistics`: STP 통계 정보를 보여줍니다.
*   **Juniper SRX Junos OS:** `show spanning-tree interface <포트>` 명령어를 사용하여 해당 포트의 STP 통계를 확인합니다.  또한, `show spanning-tree summary` 명령어를 통해 전체 STP 네트워크 상태를 확인할 수 있습니다.
    *   `show spanning-tree interface <포트>`: 해당 포트의 STP 통계 정보를 보여줍니다.
    *   `show spanning-tree summary`: 전체 STP 네트워크 상태를 보여줍니다.

**4) MAC 주소 학습 상태를 이용하여 문제 VLAN의 L2 전달 경로를 확인하는 방법 (Cisco & Juniper)**

*   **Cisco IOS XE & Juniper SRX Junos OS:** `show mac address-table` 명령어를 사용하여 문제가 발생하는 VLAN에 속한 MAC 주소가 각 스위치에서 올바르게 학습되었는지 확인합니다.  MAC 주소가 학습되지 않았다면, VLAN 트래픽 전달에 문제가 있을 가능성이 높습니다.

**5) 링크 up 및 LLDP 인식과 VLAN 트래픽 전달 성공을 서로 다른 상태로 구분해야 하는 이유**

링크가 Up(물리적 연결 정상)은 단순히 물리적인 연결이 정상이라는 의미일 뿐, VLAN 트래픽이 제대로 전달되는지 보장하지 않습니다. LLDP (Link Layer Discovery Protocol)는 장비 간의 정보를 교환하는 프로토콜이며, VLAN 정보도 포함될 수 있습니다. 하지만 LLDP 인식만으로는 VLAN 트래픽 전달이 정상적으로 이루어지고 있는지 확인할 수 없습니다.  따라서, VLAN 트래픽 전달 성공 여부를 확인하기 위해서는 추가적인 설정 확인 및 통신 테스트가 필요합니다.

**6) Cisco IOS XE 명령어와 Junos OS 명령어를 각각 구분하여 제시**

*   **Cisco IOS XE:** 위에서 언급된 명령어들을 사용합니다.
*   **Juniper SRX Junos OS:** 위에서 언급된 명령어들을 사용합니다.

**7) 한쪽 벤더의 명령어나 기능을 다른 벤더에도 동일하게 적용하지 말 것**

각 벤더의 장비는 서로 다른 아키텍처와 운영체제를 가지고 있습니다. 따라서, 특정 벤더의 명령어나 기능은 다른 벤더의 장비에 그대로 적용할 수 없습니다. 각 벤더의 문서를 참조하고, 해당 벤더의 장비에 맞는 명령어를 사용해야 합니다.

**8) 설정을 변경하기 전에 현재 상태를 확인하고 백업해야 할 항목**

*   트렁크 인터페이스 설정 (VLAN 멤버십, 캠페인 구성)
*   포트 설정 (VLAN 멤버십, STP 설정)
*   라우팅 프로토콜 설정 (RIP, OSPF 등 - 필요시)
*   전반적인 스위치 설정 (시간, NTP 서버 등)

변경 전에는 반드시 `show` 명령어 등을 통해 현재 설정을 기록하고, 가능하다면 스위치 설정 파일을 백업하여 문제 발생 시 복구할 수 있도록 준비합니다.
