## FortiGate (FortiOS 7.6) 로그 전송 문제 진단 및 점검 순서

FortiGate에서 로그 이벤트 생성부터 외부 로그 서버 전송까지의 과정에 문제가 발생하여 로그가 로컬에 쌓이지 않고 외부로 전송되지 않는 상황입니다. 외부 로그 서버는 정상 작동하고, 방화벽 정책 및 설정도 관리자가 확인한 범위 내에서 정상임을 확인했습니다. 다음은 문제 해결을 위한 점검 순서와 각 단계별 상세 내용입니다.

**주의:** 아래 내용은 FortiOS 7.6 환경을 기준으로 작성되었으며, 장비 모델 및 OS 버전에 따라 일부 명령어가 다를 수 있습니다. 정확한 명령어 문법은 Fortinet 공식 문서 또는 해당 버전의 설명서를 참조해야 합니다.

### 1단계: 로그 이벤트 생성 여부 확인 (Event Generation Check)

* **목표:** FortiGate가 실제로 로그 이벤트를 생성하는지 확인합니다.
* **점검 방법:**
    * **로그 레벨 설정 확인:** FortiGate의 로그 레벨이 너무 낮게 설정되어 있을 경우, 불필요하게 많은 로그 이벤트가 생성되어 시스템 자원을 과도하게 사용하고 전송 프로세스를 방해할 수 있습니다.
        * `system -> logging -> log settings` 메뉴에서 로그 레벨을 조정합니다. (예: "Info" 또는 "Warning")
    * **특정 이벤트 활성화:** 특정 이벤트 유형(예: 방화벽 정책 위반, 침입 시도 등)에 대한 로그를 활성화하여 해당 이벤트가 실제로 발생하고 로그로 기록되는지 확인합니다.
        * `system -> logging -> event log settings` 메뉴에서 특정 이벤트 유형의 로그 레벨을 "Enable"으로 설정합니다.
    * **CLI 명령어를 통한 이벤트 생성 테스트:**  테스트 목적으로 간단한 네트워크 트래픽을 생성하거나, FortiGate의 관리 인터페이스를 통해 특정 작업을 수행하여 로그 이벤트가 생성되는지 확인합니다.
        * `clear logs all` (모든 로그 삭제 - 주의: 데이터 손실 가능성 있음) 후, 방화벽 정책 변경 또는 네트워크 트래픽 생성 시 로그 이벤트가 생성되는지 확인합니다.

### 2단계: 로그 저장/메모리 처리 단계 확인 (Storage/Memory Processing Check)

* **목표:** 생성된 로그 이벤트가 로컬 저장소 또는 메모리 처리 단계를 정상적으로 통과하는지 확인합니다.
* **점검 방법:**
    * **로그 저장 공간 확인:**  FortiGate의 로그 저장 공간이 부족한 경우, 로그 이벤트가 제대로 저장되지 않거나 전송 프로세스가 중단될 수 있습니다.
        * `system -> logging -> log settings` 메뉴에서 "Log Storage Capacity"를 확인하고 필요에 따라 저장 공간을 늘립니다.
    * **로그 파일 크기 확인:**  로그 파일의 크기가 너무 커져서 시스템 성능에 영향을 미치는지 확인합니다.
        * CLI 명령어를 사용하여 로그 파일의 크기를 확인합니다: `show log file size` (정확한 명령어 확인이 필요합니다)
    * **로그 파일 정리 주기 설정 확인:** 로그 파일 정리 주기가 너무 길게 설정되어 있을 경우, 로그 이벤트가 오래된 상태로 남아 전송 프로세스를 방해할 수 있습니다.
        * `system -> logging -> log settings` 메뉴에서 "Log File Rotation Interval"을 조정합니다.

### 3단계: 외부 로그 서버 전송 시도 확인 (External Log Server Transmission Check)

* **목표:** FortiGate가 외부 로그 서버로 로그 이벤트를 전송하는지 확인합니다.
* **점검 방법:**
    * **로그 서버 연결 설정 확인:** FortiGate의 로그 서버 IP 주소 및 포트 설정이 정확한지 확인합니다.
        * `system -> logging -> syslog server` 메뉴에서 로그 서버 정보(IP 주소, 포트, TLS 설정 등)를 확인하고 수정합니다.
    * **방화벽 정책 확인:** FortiGate 방화벽 정책이 외부 로그 서버로 향하는 트래픽을 차단하지 않는지 확인합니다.
        * `firewall -> rules` 메뉴에서 해당 로그 서버로 향하는 트래픽 규칙이 있는지 확인하고, 필요한 경우 규칙을 추가하거나 기존 규칙을 수정합니다.
    * **Syslog 설정 확인:**  FortiGate의 Syslog 설정 (Protocol, Port, Authentication 등)이 외부 로그 서버와 호환되는지 확인합니다.
        * `system -> logging -> syslog settings` 메뉴에서 Syslog 설정을 확인하고 필요에 따라 조정합니다.

### 4단계: 로그 패킷 송신 여부 확인 (Packet Transmission Check)

* **목표:** FortiGate가 실제로 로그 패킷을 송신하는지 확인합니다.
* **점검 방법:**
    * **패킷 스니퍼 활용:** Wireshark와 같은 패킷 스니퍼를 사용하여 FortiGate와 로그 서버 간의 네트워크 트래픽을 캡처하여 로그 패킷이 송신되고 있는지 확인합니다.
        * FortiGate의 인터페이스(예: GigabitEthernet1/0)에서 패킷 스니퍼를 실행하고, 해당 인터페이스를 통해 FortiGate와 로그 서버 간의 트래픽을 캡처합니다.
    * **CLI 명령어를 통한 패킷 전송 테스트:**  `ping` 명령어를 사용하여 로그 서버로 ping 패킷을 전송하고, 해당 패킷이 정상적으로 전송되는지 확인합니다. (정확한 명령어 확인이 필요합니다)

### 5단계: 로그 서버 수신 여부 확인 (Server Reception Check)

* **목표:** 외부 로그 서버가 FortiGate로부터 로그 패킷을 실제로 수신하는지 확인합니다.
* **점검 방법:**
    * **로그 서버 로그 확인:** 로그 서버의 Syslog 또는 로그 관리 시스템에서 FortiGate로부터 송신된 로그 패킷이 기록되고 있는지 확인합니다.
    * **패킷 스니퍼 활용:** Wireshark와 같은 패킷 스니퍼를 사용하여 로그 서버 인터페이스에서 FortiGate로부터 송신된 로그 패킷을 캡처하여 정상적으로 수신되는지 확인합니다.

### 6단계: 문제 발생 구간 좁히기 (Troubleshooting & Isolation)

각 단계별 점검 결과를 바탕으로 문제 발생 구간을 좁혀나갑니다. 예를 들어, 패킷 스니퍼를 통해 로그 패킷이 송신되지만 로그 서버에 수신되지 않는다면, 네트워크 연결 상태(라우팅, 방화벽 등)를 집중적으로 검토해야 합니다.  로그 이벤트 생성 자체에는 문제가 없는 경우, 외부 로그 서버 설정 또는 네트워크 연결 문제를 의심해 볼 수 있습니다.

**중요:** 각 단계를 진행하면서 발생하는 오류 메시지, 시스템 로그 등을 기록하고 분석하여 문제의 근본적인 원인을 파악하는 데 활용합니다.

**권고하지 않는 조치:** 재부팅, 초기화, 로그 삭제 등의 조치는 데이터 손실을 야기할 수 있으므로, 문제 해결을 위한 초기 단계에서는 신중하게 고려해야 합니다.
