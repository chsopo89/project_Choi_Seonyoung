1) **현재 스위치가 NTP 서버를 실제 동기화 대상으로 사용하고 있는지 확인**  
NTP 동기화 중인 서버인지 확인하기 위해 `show ntp peers` 명령어를 실행합니다. 이 명령어는 현재 연결된 NTP 서버 목록을 보여주며, "reach" 값이 320(16진수로 0x100) 이상이고 "status"가 "synced" 또는 "valid" 상태라면 해당 서버와 동기화 중임을 나타냅니다. 또한, `show ntp associations` 명령어를 통해 정확한 동기화 관계를 확인할 수 있습니다.

2) **NTP 동기화 상태와 peer 상태에서 확인해야 할 항목**  
- `show ntp peers`: "reach", "status", "stratum", "offset" 등의 정보를 확인합니다. "status"가 "synced"인지 확인하고, "stratum"이 낮은 값(예: 1~3)인지 확인합니다.  
- `show ntp associations`: "state" 필드가 "synced"인지 확인하며, "last update" 시간과 "poll interval"을 확인해 최근 동기화 여부를 파악합니다.  
- `show ntp status`: 전체 NTP 상태를 요약적으로 보여주며, "synchronised"가 "yes"인지 확인해야 합니다.

3) **시간 관련 로컬 설정에서 추가로 확인해야 할 항목**  
- `clock timezone` 및 `clock summer-time` 명령어로 타임존 설정이 올바른지 확인합니다.  
- `ntp server <IP>` 명령어로 설정된 서버 주소가 정확한지 확인하고, `ntp authenticate` 또는 `ntp trust-key` 등 인증 설정이 있는 경우 해당 설정도 점검합니다.  
- `clock datetime` 명령어를 통해 현재 시스템 시간이 실제 시간과 일치하는지 확인합니다.

4) **NTP 서버까지의 통신과 NTP 동기화 성공 여부를 어떻게 구분할지**  
- `show ntp peers`: "reach" 값이 320(16진수로 0x100) 이상인지 확인하면 서버와 통신 중임을 알 수 있습니다.  
- `show ntp status`: "synchronised"가 "yes"인지 확인하면 동기화가 성공했음을 의미합니다.  
- `show ntp associations`: "state" 필드가 "synced"인지 확인하고, "last update" 시간이 최근인지 점검합니다.

5) **NTP 서버 주소를 변경하기 전에 어떤 증거를 확보해야 하는지**  
- 현재 설정된 NTP 서버가 정상적으로 동기화되고 있는지를 명확히 확인해야 합니다. 즉, `show ntp peers` 및 `show ntp status`에서 "synced" 상태와 "reach" 값이 320 이상임을 증명해야 합니다.  
- 해당 스위치의 NTP 설정이 다른 장비들과 차이가 없는지 비교해 보아야 하며, 특히 인증 설정이나 서버 주소 등이 동일한지 점검합니다.  
- 문제가 발생하는 시점에 NTP 로그를 확인하여 특정 시간대에 동기화 실패가 발생했는지 파악하는 것도 중요합니다. `logging monitor 7` 명령어로 디버깅 레벨을 설정하고 `show logging`으로 로그를 확인할 수 있습니다.

**참고**: 일부 IOS XE 버전에서는 `show ntp associations` 명령어의 출력 형식이 다를 수 있으므로, 정확한 명령어 사용 여부는 장비 모델 및 OS 버전에 따라 달라질 수 있습니다.
