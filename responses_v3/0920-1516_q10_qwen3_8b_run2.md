Cisco Catalyst 스위치(IOS XE)와 Juniper 스위치(Junos OS) 사이의 트렁크 연결에서 일부 VLAN 통신 실패 및 루프성 트래픽 발생 문제를 해결하기 위해, 아래와 같이 점검 순서와 각 벤더별 명령어를 구분하여 설명합니다.

---

### 1) 트렁크 인터페이스에서 실제로 허용되거나 멤버로 포함된 VLAN을 확인하는 방법  
**Cisco IOS XE**:  
```bash
show interfaces trunk
```
- 이 명령어는 트렁크 포트에 허용된 VLAN 목록을 보여줍니다.  
- **주의**: 일부 버전에서는 `show vlan` 명령어도 사용 가능할 수 있으나, 정확한 명령어 확인이 필요합니다.

**Junos OS**:  
```bash
show interfaces ge-0/0/1 unit 0 family ethernet-switching
```
- 해당 인터페이스의 VLAN 멤버십 상태를 확인합니다.  
- 또는:
```bash
show ethernet-switching table
```
- 전체 VLAN 및 포트 정보를 확인할 수 있습니다.

---

### 2) 문제가 발생하는 VLAN의 태깅 및 포트 멤버십 상태를 확인하는 방법  
**Cisco IOS XE**:  
```bash
show vlan brief
```
- VLAN ID, 포트 상태(예: `Trunk`, `Access`) 등을 확인합니다.  
- 특정 VLAN에 대한 상세 정보는:
```bash
show vlan id <VLAN_ID>
```

**Junos OS**:  
```bash
show ethernet-switching interfaces
```
- VLAN별 포트 멤버십을 보여줍니다.  
- 또는:
```bash
show ethernet-switching table
```
- VLAN과 포트의 매핑 관계를 확인할 수 있습니다.

---

### 3) STP 상태를 확인하여 새로 연결한 포트가 루프와 관련 있는지 판단하는 방법  
**Cisco IOS XE**:  
```bash
show spanning-tree interface <interface> detail
```
- 특정 인터페이스의 STP 상태(예: `Forwarding`, `Blocking`)를 확인합니다.  
- 전체 STP 정보는:
```bash
show spanning-tree summary
```

**Junos OS**:  
```bash
show spanning-tree instance default interface <interface>
```
- 해당 인터페이스의 STP 상태를 확인합니다.  
- 또는:
```bash
show spanning-tree
```
- 전체 STP 상태를 보여줍니다.

---

### 4) MAC 주소 학습 상태를 이용하여 문제 VLAN의 L2 전달 경로를 확인하는 방법  
**Cisco IOS XE**:  
```bash
show mac address-table
```
- 특정 VLAN에 대한 MAC 주소 테이블을 확인합니다.  
- 특정 VLAN에 대한 상세 정보는:
```bash
show mac address-table vlan <VLAN_ID>
```

**Junos OS**:  
```bash
show ethernet-switching table
```
- MAC 주소와 VLAN, 포트 매핑 정보를 확인할 수 있습니다.

---

### 5) 링크 up 및 LLDP 인식과 VLAN 트래픽 전달 성공을 서로 다른 상태로 구분해야 하는 이유  
- **링크 up 및 LLDP 인식**은 물리적 연결과 네트워크 인접 여부만 확인합니다.  
- **VLAN 트래픽 전달 성공**은 VLAN 구성, 포트 멤버십, STP 상태 등 L2 레이어 설정에 따라 달라집니다.  
- 따라서 두 상태는 별도로 점검해야 하며, 단순한 LLDP 인식만으로 VLAN 통신 성공을 판단할 수 없습니다.

---

### 6) Cisco IOS XE 명령어와 Junos OS 명령어를 각각 구분하여 제시  
- 위에서 이미 각 벤더별 명령어를 구분하여 제시했습니다.

---

### 7) 한쪽 벤더의 명령어나 기능을 다른 벤더에도 동일하게 적용하지 말 것  
- 예: `show interfaces trunk`은 Cisco에만 존재하며, Junos에서는 `show interfaces ge-0/0/1 unit 0 family ethernet-switching`로 대체해야 합니다.  
- VLAN 구성 방식도 Cisco는 `vlan <ID>` 명령어를 사용하고, Junos는 `edit vlans vlan-name`으로 설정합니다.

---

### 8) 설정을 변경하기 전에 현재 상태를 확인하고 백업해야 할 항목  
- **Cisco**:  
  ```bash
  show running-config | include vlan
  ```
  - VLAN 구성 정보를 백업합니다.  
- **Junos**:  
  ```bash
  show configuration | display set | match "vlans"
  ```
  - VLAN 설정을 백업합니다.

---

### 9) 루프 위험을 최소화하면서 기존 Cisco에서 Juniper로 단계적으로 트래픽을 이전하는 순서  
1. **VLAN별 분리**: 각 VLAN을 별도의 트렁크 포트에 할당하여 통신을 분리합니다.  
2. **STP 상태 확인**: 모든 VLAN에 대해 STP 상태를 점검하고, 루프 발생 가능성을 제거합니다.  
3. **MAC 주소 학습 확인**: 특정 VLAN의 MAC 테이블을 확인해 경로가 정확한지 검증합니다.  
4. **트래픽 이전**: 하나씩 VLAN을 Juniper로 전환하며, 문제가 없을 경우 다음 VLAN으로 이동합니다.

---

### 10) 각 단계에서 문제가 발생했을 때 다음 단계로 진행할지 원복할지를 판단할 기준  
- **문제 발생 시**:  
  - **원복 여부**: 해당 VLAN의 설정을 복원하고, STP 상태를 점검하여 루프 가능성 제거 후 재시도합니다.  
  - **다음 단계 진행**: 문제 해결 후, 다른 VLAN으로 이전을 계속합니다.  
- **정확한 명령어 확인이 필요합니다**. 일부 명령어는 장비 모델 및 OS 버전에 따라 다를 수 있습니다.

--- 

위 절차를 통해 Cisco와 Juniper 간의 트렁크 연결에서 발생하는 VLAN 통신 실패 및 루프성 트래픽 문제를 체계적으로 점검할 수 있습니다.
