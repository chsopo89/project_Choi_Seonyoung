## NetScreen (ScreenOS) 방화벽 및 FortiGate (FortiOS 7.6) IPsec VPN 연결 문제 진단

**개요:** NetScreen과 FortiGate 사이에 IPsec VPN이 구성되었지만, 관리 화면에서는 전체 VPN 연결 상태가 disable로 표시되는 문제를 진단하고 해결하기 위한 단계별 분석입니다. 각 장비의 관점에서 실제 통신 가능성과 관리 화면상의 오류를 구분하고, 문제 해결을 위한 검증 항목 및 점검 순서를 제시합니다.

**1. 실제 데이터 통신과 관리 화면의 VPN 상태 표시 차이 발생 이유**

* **실제 통신:** IPsec VPN 터널은 암호화된 채널을 통해 데이터를 전송하므로, 네트워크 트래픽 자체는 정상적으로 작동합니다.
* **관리 화면 (ScreenOS):** ScreenOS는 VPN 연결 상태를 실시간으로 모니터링하고 이를 사용자에게 제공합니다. 하지만, ScreenOS의 상태 정보 획득 방식은 다음과 같은 이유로 관리 화면에 표시되는 상태와 다를 수 있습니다.
    * **상태 정보 수집 주기:** ScreenOS는 특정 간격(예: 1초)마다 VPN 연결 상태를 확인하고 업데이트합니다. 이 간격 동안 문제가 발생했더라도 관리 화면에는 즉시 반영되지 않을 수 있습니다.
    * **오류 처리:** ScreenOS는 VPN 연결 실패 시 오류 메시지를 기록하지만, 이러한 메시지가 즉각적으로 관리 화면에 표시되도록 설계되어 있지 않을 수 있습니다.
    * **로그 분석:** ScreenOS는 상세한 로그 정보를 제공하며, 이를 통해 문제의 원인을 파악할 수 있습니다.

* **관리 화면 (FortiOS):** FortiGate 역시 유사한 방식으로 상태 정보를 수집 및 표시합니다. FortiOS 7.6 버전에서는 VPN 연결 상태를 보다 상세하게 모니터링하고, 오류 발생 시 알림 기능을 제공할 수 있습니다.

**2. Phase 1 & Phase 2 상태 확인 항목**

IPsec VPN은 일반적으로 Phase 1 (ISAKMP Negotiation)과 Phase 2 (Data Encryption) 두 단계로 구성됩니다. 각 단계별 상태 확인 항목은 다음과 같습니다.

* **Phase 1 (ISAKMP Negotiation):**
    * **NetScreen (ScreenOS):**
        * `show crypto isakmp sa` : ISAKMP SA(Security Association) 설정 및 상태 확인
        * `show crypto isakmp log` : ISAKMP 관련 로그 확인 (오류 메시지, 협상 실패 등)
    * **FortiGate (FortiOS):**
        * `show crypto isakmp sa` : ISAKMP SA 설정 및 상태 확인
        * `show crypto isakmp log` : ISAKMP 관련 로그 확인 (오류 메시지, 협상 실패 등)

* **Phase 2 (Data Encryption):**
    * **NetScreen (ScreenOS):**
        * `show crypto ipsec sa` : IPsec SA 설정 및 상태 확인
        * `show crypto ipsec log` : IPsec 관련 로그 확인 (오류 메시지, 암호화 실패 등)
    * **FortiGate (FortiOS):**
        * `show crypto ipsec sa` : IPsec SA 설정 및 상태 확인
        * `show crypto ipsec log` : IPsec 관련 로그 확인 (오류 메시지, 암호화 실패 등)

**3. NetScreen과 FortiGate 비교해야 할 VPN 설정 항목**

**4. 상태 표시 문제인지 실제 협상 문제인지 구분하기 위한 관측**

* **로그 분석:** 두 장비의 IPsec 관련 로그를 상세히 분석하여 오류 메시지, 협상 실패 원인 등을 파악합니다. 특히, Phase 1 및 Phase 2에서 발생하는 오류 메시지를 집중적으로 살펴봅니다.
* **패킷 캡쳐 (Packet Capture):** Wireshark와 같은 패킷 분석 도구를 사용하여 ISAKMP 및 IPsec 트래픽을 캡처하고 분석합니다. 이를 통해 실제 협상 과정에서 발생하는 문제를 진단할 수 있습니다.
* **Ping 테스트:** VPN 터널을 통해 서로 다른 네트워크에 있는 장치 간의 Ping 테스트를 수행하여 통신 가능성을 확인합니다.
* **MTU 설정 확인:** MTU(Maximum Transmission Unit) 설정이 VPN 터널 통과 시 문제가 발생하지 않도록 적절하게 구성되었는지 확인합니다.

**5. 어느 쪽 설정을 먼저 변경해야 하는지 결정하기 전에 확보해야 할 근거**

문제 해결을 위해 어떤 설정을 먼저 변경해야 하는지 결정하기 전에 다음 사항들을 확인하고 확보해야 합니다.

1.  **로그 분석 결과:** 로그 분석을 통해 Phase 1 또는 Phase 2에서 발생하는 구체적인 오류 메시지를 파악합니다.
2.  **패킷 캡쳐 결과:** 패킷 캡쳐를 통해 실제 협상 과정에서 발생하는 문제를 진단합니다.
3.  **설정 불일치 여부:** 두 장비의 VPN 설정 항목을 비교하여 불일치가 있는지 확인합니다. 특히, PSK, 인증서, IKE 버전 등 핵심 설정 항목의 일치를 확인합니다.
4.  **네트워크 환경:** 네트워크 구성(라우팅, 방화벽 규칙 등)이 IPsec VPN 연결에 영향을 미치지 않는지 확인합니다.

**결론:**

위의 단계별 분석과 검증 과정을 통해 NetScreen과 FortiGate 사이의 IPsec VPN 연결 문제의 원인을 정확하게 진단하고 해결할 수 있습니다. 문제 해결은 로그 분석, 패킷 캡쳐, 설정 비교 등을 통해 이루어져야 하며, 문제 발생 시 각 장비의 설정을 변경하기 전에 충분한 근거를 확보해야 합니다.
