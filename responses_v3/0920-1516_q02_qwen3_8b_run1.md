1) **외부 클라이언트의 요청이 FortiGate까지 도착하는지 확인하는 방법**  
   - 외부에서 VIP에 대한 패킷 트래픽이 도달하고 있는지 확인하기 위해 `diagnose sys session list` 명령어를 사용하여 세션 목록을 확인합니다. 이 명령어는 현재 활성화된 세션 정보를 보여주며, 외부 클라이언트가 VIP로 접근했는지를 알 수 있습니다.  
   - 또한, `diag debug flow enable` 명령어를 통해 흐름 디버깅을 활성화한 후, `tcpdump` 또는 `diag debug flow show`를 이용해 패킷이 FortiGate에 도착하는지 확인할 수도 있습니다.

2) **FortiGate가 해당 요청을 올바른 VIP와 정책에 매칭하는지 확인하는 방법**  
   - `diagnose firewall policy list` 명령어를 사용하여 현재 활성화된 방화벽 정책 목록을 확인합니다. 이 명령어는 정책 번호, 소스/대상 IP, 서비스 등을 보여주며, VIP에 대한 정책이 있는지 확인할 수 있습니다.  
   - 또한, `diagnose firewall session list` 명령어로 세션 정보를 확인하면, 요청이 어떤 정책과 연결되었는지를 알 수 있습니다.

3) **VIP 변환 이후 웹 서버 방향으로 패킷이 전달되는지 확인하는 방법**  
   - `diagnose sys session list` 명령어를 통해 세션의 상태를 확인합니다. 특히, "state" 필드가 "established" 또는 "open"인지 확인하여 패킷이 웹 서버로 전달되고 있는지 파악합니다.  
   - `tcpdump` 명령어를 사용해 FortiGate에서 웹 서버로 전송되는 패킷을 캡처하여 실제 데이터 흐름을 확인할 수도 있습니다.

4) **웹 서버의 응답 패킷이 어떤 경로로 돌아오는지 확인해야 하는 이유**  
   - 외부 클라이언트는 VIP를 통해 요청을 보내고, FortiGate가 해당 요청을 웹 서버로 전달한 후, 웹 서버는 응답을 보냅니다. 이 응답 패킷이 FortiGate로 돌아오기 위해 정상적인 경로를 따라야 합니다. 만약 응답 패킷이 잘못된 경로로 돌아가면, 클라이언트는 응답을 받지 못하게 되므로 서비스 중단 현상이 발생할 수 있습니다.

5) **각 단계의 관측 결과에 따라 다음 점검 위치를 어떻게 결정할지**  
   - 첫째, 외부 클라이언트의 요청이 FortiGate에 도달하는지 확인합니다. 만약 요청이 도달하지 않으면, 네트워크 장애나 라우팅 문제를 의심해야 합니다.  
   - 둘째, 요청이 올바른 VIP와 정책에 매칭되는지 확인합니다. 만약 매칭되지 않는다면, 정책 설정이나 VIP 구성에 문제가 있을 가능성이 큽니다.  
   - 셋째, 패킷이 웹 서버로 전달되고 있는지 확인합니다. 만약 전달되지 않는다면, NAT 변환 또는 방화벽 정책의 오류가 원인일 수 있습니다.  
   - 넷째, 응답 패킷이 올바르게 돌아오는지 확인합니다. 이는 라우팅 설정, NAT 구성, 또는 방화벽 정책에서 문제를 찾을 수 있습니다.  
   - 각 단계에서 관측 결과에 따라 점검 위치를 좁혀 나가며, 문제가 발생하는 구간을 파악해야 합니다. 이미 정상이라고 제시된 항목은 무리하게 재설정하지 않고, 관측을 통해 문제 구간을 체계적으로 분석해야 합니다.
