## FortiGate (FortiOS 7.6) 로그 전송 문제 진단 및 점검 순서

FortiGate에서 로그 이벤트 생성부터 외부 로그 서버 전송까지의 과정에 문제가 발생하여 로그가 로컬에 쌓이지 않고 외부로 전송되지 않는 상황입니다. 외부 로그 서버는 정상 작동하고, 방화벽 정책 및 설정도 관리자가 확인한 범위 내에서 정상임을 감안하여, 아래와 같이 단계별 점검을 진행합니다.

**주의:** FortiOS 7.6 버전 정보이므로, 최신 버전과의 차이가 있을 수 있습니다. 또한, 특정 장비 모델에 따라 설정 옵션이나 명령어에 약간의 차이가 있을 수 있습니다.

### 1단계: 로그 이벤트 생성 여부 확인 (Event Generation)

* **목표:** FortiGate에서 실제로 로그 이벤트를 생성하는지 확인합니다.
* **점검 방법:**
    * **로그 레벨 설정 확인:** FortiGate의 각 인터페이스 및 정책에 대한 로그 레벨 설정이 너무 낮게 설정되어 있는지 확인합니다. 예를 들어, 모든 트래픽에 대해 `Info` 레벨로 설정하면 불필요한 로그가 많이 생성될 수 있습니다.  `system logging` 메뉴에서 각 항목별 로그 레벨을 조정해봅니다.
    * **정책 로그 활성화:** 특정 방화벽 정책에 대한 로그를 활성화하여 해당 정책으로 인해 발생하는 이벤트가 기록되는지 확인합니다.
    * **CLI 명령 사용 (정확한 명령어 확인이 필요합니다):** `show log statistics` 명령어를 사용하여 현재 로그 이벤트의 총 개수와 유형별 분포를 확인합니다. 이 정보는 로그 이벤트가 실제로 생성되고 있는지, 어떤 유형의 이벤트가 주로 발생하고 있는지를 파악하는 데 도움이 됩니다.
* **기대 결과:** 로그 이벤트가 생성되고 있으며, 예상되는 유형의 이벤트가 기록되고 있어야 합니다.

### 2단계: 로컬 저장/메모리 처리 단계 확인 (Local Storage/Memory Processing)

* **목표:** 생성된 로그 이벤트가 로컬 저장소 또는 메모리 처리 단계를 거치는지 확인합니다.
* **점검 방법:**
    * **로컬 디스크 공간 확인:** FortiGate의 로컬 디스크 공간이 부족하지 않은지 확인합니다. 로그 파일이 로컬에 저장되기 때문에 디스크 공간 부족은 로그 전송 문제를 유발할 수 있습니다. `show storage` 명령어를 사용하여 디스크 사용량을 확인합니다.
    * **로그 파일 크기 및 생성 빈도 확인:**  로그 파일의 크기와 생성 빈도를 확인하여 로그 이벤트가 정상적으로 생성되고 있는지, 그리고 너무 짧은 간격으로 로그가 생성되어 디스크 공간을 초과하는지 확인합니다.
    * **CLI 명령 사용 (정확한 명령어 확인이 필요합니다):** `show log file <log_file_name>` 명령어를 사용하여 특정 로그 파일의 내용을 확인하고, 이벤트가 제대로 기록되고 있는지 검토합니다.
* **기대 결과:** 로그 이벤트가 로컬에 저장되고, 적절한 간격으로 로그 파일이 생성/업데이트되는 것을 확인할 수 있어야 합니다.

### 3단계: 외부 로그 서버 전송 시도 확인 (External Server Transmission)

* **목표:** FortiGate에서 외부 로그 서버로 전송을 시도하는지 확인합니다.
* **점검 방법:**
    * **로그 서버 설정 확인:** FortiGate의 로그 서버 설정(IP 주소, 포트, 인증 정보 등)이 정확하게 구성되어 있는지 확인합니다.  `system logging` 메뉴에서 로그 서버 설정을 검토합니다.
    * **방화벽 정책 확인:** FortiGate 방화벽 정책에 의해 외부 로그 서버로의 트래픽이 차단되지 않았는지 확인합니다.  특정 IP 주소 또는 포트에 대한 접근을 허용하도록 정책을 조정해야 할 수 있습니다.
    * **CLI 명령 사용 (정확한 명령어 확인이 필요합니다):** `show log syslog config` 명령어를 사용하여 로그 서버 설정 정보를 확인합니다.
* **기대 결과:** FortiGate가 외부 로그 서버로 로그 데이터를 전송하려고 시도하는 것을 확인할 수 있어야 합니다.

### 4단계: 로그 패킷 송신 여부 확인 (Packet Transmission)

* **목표:** FortiGate에서 실제로 로그 패킷을 송신하는지 확인합니다.
* **점검 방법:**
    * **네트워크 트래픽 모니터링:** Wireshark와 같은 네트워크 분석 도구를 사용하여 FortiGate와 로그 서버 간의 네트워크 트래픽을 캡처하고 분석합니다.  FortiGate에서 로그 데이터를 전송하는 패킷이 존재하는지 확인합니다.
    * **포트 스캔:** 로그 서버 포트로 포트 스캔을 수행하여 해당 포트에 연결을 시도하고, FortiGate가 응답하는지 확인합니다.
* **기대 결과:** FortiGate에서 로그 데이터를 포함한 패킷을 외부 로그 서버로 송신하는 것을 확인할 수 있어야 합니다.

### 5단계: 로그 서버 수신 여부 확인 (Server Reception)

* **목표:** 로그 서버가 FortiGate로부터의 로그 패킷을 실제로 수신하는지 확인합니다.
* **점검 방법:**
    * **로그 서버 로그 확인:** 로그 서버의 로그 파일 또는 시스템 로그를 확인하여 FortiGate로부터의 로그 패킷 수신에 대한 기록이 있는지 확인합니다.
    * **네트워크 분석 도구 사용:** Wireshark와 같은 네트워크 분석 도구를 사용하여 로그 서버에서 FortiGate로부터의 트래픽을 캡처하고 분석합니다.  로그 데이터가 패킷 형태로 수신되는 것을 확인할 수 있어야 합니다.
* **기대 결과:** 로그 서버가 FortiGate로부터의 로그 패킷을 정상적으로 수신하는 것을 확인할 수 있어야 합니다.

### 6단계: 문제 구간 좁히기 (Troubleshooting)

각 단계별 결과를 종합적으로 검토하여 문제 발생 지점을 좁혀나갑니다. 예를 들어, 4단계에서 패킷 송신이 확인되지만 5단계에서 로그 서버 수신이 확인되지 않는다면, 네트워크 경로에 문제가 있을 가능성이 높습니다.  방화벽 설정, 라우팅 테이블, 네트워크 연결 상태 등을 다시 한번 점검해야 합니다.

**추가 고려 사항:**

* **시간 동기화:** FortiGate와 로그 서버 간의 시간 동기화가 제대로 이루어지고 있는지 확인합니다. 시간 차이는 로그 데이터 분석에 혼란을 야기할 수 있습니다. `system clock` 명령어를 사용하여 시간 동기화를 확인하고 조정합니다.
* **인증/권한 설정:** 로그 서버로 전송되는 로그 데이터에 대한 인증 및 권한 설정이 올바르게 구성되어 있는지 확인합니다.

위의 점검 순서를 따라 문제 해결을 시도해 보시고, 각 단계별 결과를 상세하게 기록하여 문제 해결 과정을 추적하는 것이 중요합니다.  만약 위 방법으로도 문제가 해결되지 않는다면, Fortinet 기술 지원팀에 문의하여 전문적인 도움을 받는 것을 고려해야 합니다.
