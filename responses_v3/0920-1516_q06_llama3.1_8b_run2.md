네트워크 엔지니어로서, Cisco Catalyst 스위치(IOS XE)에 발생하는 NTP 동기화 문제를 해결하기 위해 다음 단계로 문제를 분석해 보겠습니다.

**1. 현재 스위치가 NTP 서버를 실제 동기화 대상으로 사용하고 있는지**

NTP 서버를 설정했지만 시간이 다시 어긋나 있다면, 스위치는 NTP 서버와 연결되어 있지 않을 가능성이 있습니다. 이 경우, 다음 명령어를 통해 NTP 서버의 상태를 확인할 수 있습니다.

```bash
show ntp association
```

이 명령어는 현재 스위치가 NTP 서버와 연결된 상태인지, 또는 연결을 시도하는 중인지를 알려줍니다. 만약 'no associations'이라고 표시된다면, 스위치는 NTP 서버와 연결되지 않은 것입니다.

**2. NTP 동기화 상태와 peer 상태에서 무엇을 확인해야 하는지**

NTP 동기화 상태를 확인하려면 다음 명령어를 사용합니다.

```bash
show ntp status
```

이 명령어는 현재 스위치의 NTP 동기화 상태를 알려줍니다. 만약 'synchronized'이라고 표시된다면, 스위치는 NTP 서버와 정상적으로 동기화된 것입니다. 그러나 시간이 다시 어긋나 있다면, 이 경우에는 다른 문제가 발생한 것으로 보입니다.

peer 상태를 확인하려면 다음 명령어를 사용합니다.

```bash
show ntp peers
```

이 명령어는 현재 스위치가 NTP 서버와 연결된 peer 목록을 보여줍니다. 만약 peer 목록에 NTP 서버가 없다면, 스위치는 NTP 서버와 연결되지 않은 것입니다.

**3. 시간 관련 로컬 설정에서 추가로 확인해야 할 항목은 무엇인지**

시간 관련 로컬 설정을 확인하려면 다음 명령어를 사용합니다.

```bash
show clock detail
```

이 명령어는 현재 스위치의 시스템 시각과 시간 관련 설정을 알려줍니다. 만약 'clock timezone'이 잘못된 값으로 설정되어 있다면, 이는 시간 동기화 문제의 원인일 수 있습니다.

또한, 다음 명령어를 통해 로컬 시간 설정을 확인할 수 있습니다.

```bash
show running-config | include clock timezone
```

이 명령어는 현재 스위치의 로컬 시간 설정을 보여줍니다. 만약 잘못된 값으로 설정되어 있다면, 이를 수정해야 합니다.

**4. NTP 서버까지의 통신과 NTP 동기화 성공 여부를 어떻게 구분할지**

NTP 서버까지의 통신은 다음 명령어를 사용하여 확인할 수 있습니다.

```bash
debug ntp packet
```

이 명령어는 NTP 패킷 전송 및 수신에 대한 디버그 정보를 제공합니다. 만약 'ntp packet' 관련 오류 메시지가 표시된다면, 이는 NTP 서버와 연결되지 않은 것입니다.

NTP 동기화 성공 여부는 위에서 설명한 `show ntp status` 명령어를 통해 확인할 수 있습니다.

**5. 이 상황에서 NTP 서버 주소를 변경하기 전에 어떤 증거를 확보해야 하는지**

NTP 서버 주소가 잘못된 경우, 스위치는 NTP 서버와 연결되지 않습니다. 따라서, 다음 증거를 확보해야 합니다.

* `show ntp association` 명령어로 NTP 서버의 상태를 확인합니다.
* `show ntp peers` 명령어로 peer 목록을 확인합니다.
* `debug ntp packet` 명령어로 NTP 패킷 전송 및 수신에 대한 디버그 정보를 제공합니다.

이러한 증거를 확보한 후, NTP 서버 주소를 변경할 수 있습니다.
