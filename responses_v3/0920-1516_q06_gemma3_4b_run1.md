## Cisco Catalyst 스위치(IOS XE) NTP 시간 동기화 문제 해결 단계별 가이드

Cisco Catalyst 스위치(IOS XE)에서 NTP 설정 후 시간이 다시 어긋나는 문제는 여러 원인으로 발생할 수 있습니다. 아래는 문제 해결을 위한 단계별 접근 방식입니다.

**1단계: 현재 스위치가 NTP 서버를 실제 동기화 대상으로 사용하고 있는지 확인**

* **문제 진단:** 스위치가 NTP 서버로부터 정보를 받아 시간을 동기화하는지, 혹은 단순히 NTP 서버와의 peer 관계만 유지하고 있는지를 파악해야 합니다.
* **확인 명령어 (IOS XE):**
    * `show ntp status`:  NTP 상태를 보여줍니다. 'Synchronized' 상태인지, 'Desync' 상태인지 확인합니다. ‘Desync’ 상태라면 시간 차이가 발생하고 있음을 의미합니다.
    * `show ntp associations`: 현재 설정된 NTP 서버(peer) 목록을 보여줍니다. 각 peer의 상태와 시간 오차(deviation)를 확인할 수 있습니다.
    * `show clock timezone`: 스위치의 로컬 시계 정보와 UTC 시계 정보를 비교하여 시간 차이를 확인합니다.

**2단계: NTP 동기화 상태 및 Peer 상태에서 추가적인 확인 사항**

* **NTP 동기화 상태:**
    * `show ntp status` 명령어를 통해 'Synchronized' 상태인지 확인합니다. Synchronized 상태가 아니면, NTP 서버와의 연결 문제, 시간 오차 허용 범위 초과, 또는 스위치 자체의 문제일 가능성이 높습니다.
    * ‘Desync’ 상태라면, `show ntp associations` 명령어를 통해 시간 오차(deviation)를 확인하고, 이 값이 지속적으로 증가한다면 NTP 서버 설정 오류나 네트워크 문제를 의심해야 합니다.
* **Peer 상태:**
    * `show ntp associations` 명령어를 통해 각 peer의 상태를 확인합니다.
        * **상태:**  ‘Up’, ‘Down’, ‘Hold Time Exceeded’ 등의 상태를 확인하여 정상적인 peer 관계인지 판단합니다.
        * **Deviation (시간 오차):** Deviation 값이 0이 아니면 시간 동기화에 문제가 있음을 나타냅니다. Deviation 값이 클수록 시간 차이가 크다는 의미입니다.
        * **Reachability (접근성):**  Peer에 대한 접근성이 있는지 확인합니다. 네트워크 문제로 인해 Peer에 도달하지 못하면 동기화가 불가능합니다.

**3단계: 시간 관련 로컬 설정에서 추가 확인 사항**

* **Clock Source:** 스위치의 Clock Source가 ‘NTP’로 설정되어 있는지 확인합니다. 다른 Clock Source(예: Manual)로 설정되어 있으면 NTP를 통한 동기화가 이루어지지 않습니다.
    * `show clock timezone` 명령어를 통해 현재 Clock Source를 확인할 수 있습니다.
* **Stratum Level:** Stratum 레벨은 NTP 서버와의 계층 구조를 나타냅니다. Stratum 1 서버는 직접 NTP 패킷을 전송하고, Stratum 2 서버는 Stratum 1 서버로부터 정보를 받아 시간을 동기화합니다.  스위치가 Stratum 1 서버에 연결되지 않은 경우 시간 정확도가 떨어질 수 있습니다.
    * `show ntp associations` 명령어를 통해 스위치의 Stratum 레벨을 확인합니다.
* **Delay & Round-trip Time (RTT):** Delay와 RTT 값은 NTP 서버까지의 네트워크 지연 및 응답 시간을 나타냅니다.  이 값이 높으면 시간 동기화에 영향을 줄 수 있습니다.
    * `show ntp associations` 명령어를 통해 Delay와 RTT 값을 확인하고, 비정상적으로 높은 값은 네트워크 문제를 의심해야 합니다.

**4단계: NTP 서버까지의 통신과 NTP 동기화 성공 여부 구분**

* **통신 확인:** 스위치가 NTP 서버에 정상적으로 패킷을 전송하고 있는지 확인합니다.
    * `ping <NTP 서버 IP 주소>` 명령어를 사용하여 NTP 서버에 대한 ICMP 패킷 전송 가능성을 확인합니다.
    * `traceroute <NTP 서버 IP 주소>` 명령어를 사용하여 NTP 서버까지의 경로를 추적하고, 네트워크 병목이나 장애가 있는지 확인합니다.
* **동기화 성공 여부 확인:** NTP 서버로부터 응답을 받고, 스위치의 시계가 NTP 서버의 시간으로 업데이트되었는지 확인합니다.
    * `show ntp status` 명령어를 통해 'Synchronized' 상태인지 확인합니다.
    * `show clock timezone` 명령어를 통해 로컬 시계 정보와 UTC 시계 정보가 일치하는지 확인합니다.

**5단계: NTP 서버 주소를 변경하기 전에 확보해야 할 증거**

NTP 서버 주소를 변경하기 전에 다음 사항들을 확실하게 확인하고 기록해야 합니다. 이는 문제 발생 시 원인을 파악하고, 변경 후에도 동일한 문제가 재발하지 않도록 하는 데 중요합니다.

1. **현재 동기화 설정:** 현재 스위치가 어떤 NTP 서버에 동기화되어 있는지, 시간 오차 허용 범위는 얼마인지, Stratum 레벨은 무엇인지 등 모든 동기화 설정을 꼼꼼히 기록합니다.
2. **Peer 관계:** 현재 설정된 NTP 서버(peer) 목록을 정확하게 기록합니다.
3. **NTP 서버 응답 정보:** NTP 서버로부터 정상적으로 응답을 받고 있는지 확인하는 로그 또는 네트워크 트래픽 정보를 수집합니다. (예: `show ntp associations` 출력 내용, NTP 패킷 캡쳐)
4. **시간 변화 추적:** NTP 서버 주소 변경 전후의 시간 변화를 지속적으로 모니터링하고 기록합니다.  이 데이터는 변경 후 문제가 발생했을 때 비교 분석하는 데 사용됩니다.

**주의사항:**

*   IOS XE 버전 및 스위치 모델에 따라 명령어와 설정 옵션이 다를 수 있습니다. 정확한 명령어 확인이 필요합니다.
*   NTP 서버 자체의 문제일 가능성도 배제하지 마십시오. NTP 서버의 상태를 확인하고, 다른 장비에서도 동일한 문제를 경험하는지 확인해야 합니다.
*   네트워크 환경(라우터, 방화벽 등)이 NTP 트래픽을 차단하지 않는지 확인합니다.

위 단계를 통해 문제의 근본 원인을 파악하고, NTP 설정을 정상적으로 구성하여 시간 동기화를 안정적으로 유지할 수 있을 것입니다.
