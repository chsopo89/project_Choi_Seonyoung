## Cisco Catalyst (IOS XE) - Juniper SRX (Junos OS) 스위치 간 VLAN 통신 문제 진단 및 해결

Cisco Catalyst 스위치와 Juniper SRX 스위치를 전환하는 과정에서 발생하는 VLAN 트래픽 전달 실패 및 루프성 트래픽 문제는 복잡하게 얽혀 있을 가능성이 높습니다. 아래는 점검 순서대로 상세 분석 및 해결 방안입니다. 장비 모델 및 OS 버전 정보가 부족하므로, 일반적인 설정과 명령어를 기준으로 설명하며, 실제 환경에 맞게 조정해야 합니다.

**1. 트렁크 인터페이스에서 실제로 허용되거나 멤버로 포함된 VLAN을 확인하는 방법**

* **Cisco IOS XE:**
    `show interface <트렁크 인터페이스> vlan brief` - 해당 트렁크 인터페이스에 속한 VLAN ID와 상태를 보여줍니다.
    `show running-config interface <트렁크 인터페이스>` - 트렁크 인터페이스의 구성 내용을 확인하여 VLAN 멤버십이 올바르게 설정되었는지 확인합니다.
* **Juniper SRX (Junos OS):**
    `show configuration interfaces <트렁크 인터페이스> | match vlan` - 트렁크 인터페이스의 구성에서 VLAN 정보를 필터링하여 보여줍니다.
    `show configuration interfaces <트렁크 인터페이스>` - 트렁크 인터페이스의 전체 구성 내용을 확인하여 VLAN 멤버십이 올바르게 설정되었는지 확인합니다.

**2. 문제가 발생하는 VLAN의 태깅 및 포트 멤버십 상태를 확인하는 방법**

* **Cisco IOS XE:**
    `show vlans summary` - 모든 VLAN의 상태를 요약하여 보여줍니다.
    `show interface <포트> switchport` - 해당 포트의 스위치포트 설정 (태깅, VLAN 멤버십 등)을 확인합니다.
* **Juniper SRX (Junos OS):**
    `show configuration vlan <VLAN ID>` - 특정 VLAN의 구성 내용을 확인합니다.
    `show configuration interfaces <포트> | match vlan` - 해당 포트의 VLAN 멤버십 정보를 확인합니다.

**3. STP 상태를 확인하여 새로 연결한 포트가 루프와 관련 있는지 판단하는 방법**

* **Cisco IOS XE:**
    `show spanning-tree statistics` - STP 통계를 보여줍니다. 특히 새로운 포트가 어떤 브랜치 또는 포트 인스터브리브 상태인지 확인합니다.
    `show running-config spanning-tree` - STP 설정 (예: RSTP 우선순위)을 확인합니다.
* **Juniper SRX (Junos OS):**
    `show spanning-tree interface <포트>` - 해당 포트의 STP 통계를 보여줍니다.
    `show configuration spanning-tree` - STP 설정을 확인합니다.  (RSTP와 유사한 동작을 제공)

**4. MAC 주소 학습 상태를 이용하여 문제 VLAN의 L2 전달 경로를 확인하는 방법**

* **Cisco IOS XE:**
    `show mac address-table interface <포트>` - 해당 포트에서 학습된 MAC 주소를 보여줍니다. 문제가 발생하는 VLAN에 속한 MAC 주소가 올바르게 학습되었는지 확인합니다.
* **Juniper SRX (Junos OS):**
    `show mac address-table interface <포트>` - 해당 포트에서 학습된 MAC 주소를 보여줍니다.

**5. 링크 up 및 LLDP 인식과 VLAN 트래픽 전달 성공을 서로 다른 상태로 구분해야 하는 이유**

링크가 Up(Physical Layer)으로 연결되어 있다는 것은 물리적인 연결이 정상이라는 의미일 뿐, VLAN 트래픽이 제대로 전달되는지 보장하지 않습니다. LLDP(Link Layer Discovery Protocol)는 장비 간의 정보를 교환하여 네트워크 토폴로지를 파악하는 데 사용되지만, VLAN 트래픽 전달 자체를 보장하지 않습니다.  따라서, 물리적 연결 상태와 VLAN 트래픽 전달 상태는 별개로 확인해야 합니다.

**6. Cisco IOS XE 및 Junos OS 명령어 구분**

| 기능             | Cisco IOS XE (예시) | Juniper SRX (Junos OS) (예시) |
|------------------|----------------------|-----------------------------|
| 인터페이스 정보   | `show interface <인터페이스>` | `show configuration interfaces <인터페이스>` |
| VLAN 정보        | `show vlan summary`    | `show configuration vlan <VLAN ID>` |
| STP 통계          | `show spanning-tree statistics` | `show spanning-tree interface <포트>` |
| MAC 주소 테이블     | `show mac address-table interface <포트>` | `show mac address-table interface <포트>` |

**7. 한쪽 벤더의 명령어나 기능을 다른 벤더에도 동일하게 적용하지 말 것**

각 벤더의 장비는 고유한 명령어 및 기능 설정을 가지고 있습니다.  Cisco IOS XE에서 사용되는 명령어를 Junos OS에 직접 적용하는 것은 예상치 못한 문제를 발생시킬 수 있습니다. 각 벤더의 문서를 참조하여 해당 벤더의 명령어를 사용해야 합니다.

**8. 설정을 변경하기 전에 현재 상태를 확인하고 백업해야 할 항목**

* **전체 구성 백업:** Cisco IOS XE에서는 `copy running-config startup-config` 명령어를, Junos OS에서는 `request system configuration save` 명령어를 사용하여 전체 구성을 백업합니다.
* **문제 VLAN 설정 확인:** 문제 VLAN의 멤버십, 태깅 설정 등을 기록해 둡니다.
* **STP 설정 확인:** STP 우선순위, RSTP 활성화 여부 등 관련 설정을 기록해 둡니다.

**9. 루프 위험을 최소화하면서 기존 Cisco에서 Juniper로 단계적으로 트래픽을 이전하는 순서**

1.  **Isolated Testing:**  두 스위치를 연결하고, 문제가 발생하는 VLAN에 대한 트래픽만 전달하도록 제한된 환경에서 테스트를 진행합니다.
2.  **Limited VLAN Migration:**  하나 또는 두 개의 VLAN만 먼저 Juniper 스위치로 이전합니다.  이때, STP 및 MAC 주소 학습 상태를 면밀히 모니터링합니다.
3.  **Full VLAN Migration:**  모든 VLAN을 Juniper 스위치로 이전합니다.  전체 네트워크의 트래픽 흐름을 지속적으로 모니터링하며, 문제 발생 시 즉시 이전 단계를 재실행합니다.

**10. 각 단계에서 문제가 발생했을 때 다음 단계로 진행할지 원복할지를 판단할 기준**

* **루프성 트래픽 발생:** 즉시 이전 단계를 재실행하고, STP 설정 (예: 우선순위 조정)을 확인합니다.
* **VLAN 트래픽 전달 실패:** 해당 VLAN의 멤버십 및 태깅 설정을 다시 확인하고, MAC 주소 학습 상태를 확인합니다.
* **MAC 주소 테이블 불일치:**  두 스위치의 MAC 주소 테이블이 일치하는지 확인하고, 필요하다면 수동으로 MAC 주소를 학습시킵니다.
* **
