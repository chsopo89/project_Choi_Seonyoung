FortiGate에서는 다음 5단계를 분리해 확인해야 합니다.

1. **로그 생성 여부**
2. **FortiGate 내부 저장 여부**
3. **로그 전송 프로세스가 전송을 시도하는지**
4. **실제 로그 패킷이 FortiGate에서 송신되는지**
5. **로그 서버가 패킷을 수신하고 처리하는지**

장비 모델, FortiOS 빌드, 로그 방식(Syslog/FortiAnalyzer), 전송 프로토콜(UDP/TCP/TLS)에 따라 메뉴와 명령이 달라질 수 있습니다. 먼저 버전을 확인합니다.

```text
get system status
```

## 1. 로그 생성 단계 확인

먼저 실제로 로그가 발생할 트래픽이나 이벤트를 재현합니다.

- 정책에 로그 기록이 활성화되어 있는지 확인
- 해당 트래픽이 실제 정책에 매칭되는지 확인
- 정책 순서, 암시적 거부, 세션 캐시 여부 확인
- `utm`, `traffic`, `event` 등 필요한 로그 유형이 활성화되어 있는지 확인
- 관리 접속 로그, 시스템 이벤트 등 다른 유형의 로그도 생성되는지 비교

정책 설정은 다음과 같이 확인할 수 있습니다.

```text
show full-configuration firewall policy
```

특정 트래픽에 대해 정책 로그는 생성되지만 UTM·웹필터 로그만 없다면, 로그 서버 문제가 아니라 UTM 프로파일 또는 해당 이벤트 자체의 로그 생성 문제일 수 있습니다.

로그 생성 여부는 GUI의 **Log & Report**에서 먼저 확인하는 것이 안전합니다. GUI에도 아무 로그가 없다면 외부 전송을 점검하기 전에 생성 조건과 정책을 확인해야 합니다.

## 2. FortiGate 내부 저장 단계 확인

외부 로그 서버를 잠시 제외하고, FortiGate의 메모리 또는 디스크 로그에 기록되는지 확인합니다.

설정을 확인합니다.

```text
show full-configuration log memory setting
show full-configuration log disk setting
```

장비 모델에 따라 디스크가 없거나 디스크 로깅 기능이 제공되지 않을 수 있습니다. 또한 FortiGate는 설정, 라이선스, 저장장치 상태에 따라 메모리 또는 디스크 로그를 보존하지 않을 수 있습니다.

GUI에서 다음을 확인합니다.

- **Log & Report**에 현재 로그가 표시되는지
- 로그 저장 위치가 Memory 또는 Disk로 설정되어 있는지
- 메모리 로그가 가득 차서 오래된 로그가 순환 삭제되는지
- 디스크 상태와 사용률에 이상이 없는지
- 로그 필터 때문에 화면에 보이지 않는 것은 아닌지

여기서 로그가 생성되어 로컬 화면에 보이지만 로그 서버에만 없다면, 문제 범위는 대체로 **외부 전송 설정, 로그 데몬, 경로·포트, 또는 수신 측**으로 좁혀집니다.

로그 데몬 동작을 확인할 때는 짧은 시간만 디버깅합니다.

```text
diagnose debug reset
diagnose debug application miglogd 255
diagnose debug enable
```

그 상태에서 테스트 로그를 발생시키고 메시지를 관찰합니다. 종료할 때는 반드시 디버그를 끕니다.

```text
diagnose debug disable
diagnose debug reset
```

`miglogd` 관련 오류, 큐 적체, 저장 실패, 전송 실패 메시지가 있는지 확인합니다. 디버그 출력은 FortiOS 빌드별로 다를 수 있으므로 특정 문자열이 없다고 정상으로 단정하지 않습니다.

## 3. 외부 로그 전송 시도 단계 확인

로그 서버 설정을 확인합니다.

Syslog라면:

```text
show full-configuration log syslogd setting
```

FortiAnalyzer라면 해당 장비의 설정 항목을 별도로 확인해야 하며, 장비와 설정 방식에 따라 명령어가 달라질 수 있습니다. 정확한 명령어 확인이 필요합니다.

다음 항목을 대조합니다.

- 서버 IP 또는 FQDN
- 전송 프로토콜 UDP/TCP/TLS
- 포트 번호
- VDOM별 로그 설정
- 로그 전송 대상과 source IP
- 로컬 로그 저장은 되지만 외부 전송이 비활성화되어 있지 않은지
- 전송 큐 또는 인증서/TLS 오류 여부

Ping이 정상이어도 다음은 보장하지 않습니다.

- UDP/TCP 로그 포트 도달
- 올바른 source IP 사용
- 올바른 VDOM의 라우팅
- 서버의 방화벽 허용
- TLS 인증 성공

전송 시도 자체는 `miglogd
