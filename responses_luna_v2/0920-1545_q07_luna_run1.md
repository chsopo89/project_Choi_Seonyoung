## 1. 먼저 장애 범위를 좁히는 방법

Juniper의 HA 전환이 정상이라는 사실만으로 Cisco를 원인으로 단정하면 안 됩니다. 우선 **양 장비의 이벤트 시간과 공통 연결 구간**을 비교합니다.

판단 기준은 다음과 같습니다.

- Juniper의 HA 전환은 정상이고, Juniper의 대기 장비가 정상적으로 트래픽을 처리함
- Cisco는 Active 장비만 꺼지고 Standby가 Active로 승격되지 않음
- Cisco의 HA 제어 링크, 전용 링크, 전원, 부팅 상태에 이상이 있음

위 조건이면 우선 **Cisco HA 전환 실패 또는 Cisco Active 장비의 전원·하드웨어 장애**로 범위를 좁힙니다.

반대로 Cisco와 Juniper 사이 링크가 동시에 Down 되었고, Cisco HA 제어 링크까지 동일한 경로를 사용한다면 단순한 링크 장애가 HA 실패를 유발했을 가능성도 확인해야 합니다. 따라서 다음 순서가 적절합니다.

1. 장애 시각과 양 장비의 로그 시각 대조
2. Cisco Active/Standby의 HA 상태 확인
3. Cisco Active 장비의 전원·부팅·크래시 여부 확인
4. Cisco-Juniper 사이 물리 링크 확인
5. LACP, STP, 포트채널 등 논리 프로토콜 확인
6. 링크 장애인지 HA 전환 실패인지 분리 판정

Cisco의 HA 방식이 StackWise, StackWise Virtual, VSS, Nexus vPC 등인지에 따라 명령어와 정상 상태가 다릅니다. 모델과 OS 버전이 없으므로 HA 전용 명령어는 장비 확인 후 적용해야 합니다.

## 2. Cisco 측 HA 상태와 구성 확인

먼저 다음 기본 정보를 확보합니다.

```text
show version
show clock
show running-config
show logging
```

확인 항목은 다음과 같습니다.

- Cisco 모델, IOS/IOS XE/NX-OS 버전
- HA 구성 방식
- Active/Standby 또는 Active/Member 역할
- HA 제어 링크와 데이터 링크의 구성
- 마지막 재부팅 시간
- 전원 장애, watchdog, crash, kernel panic, supervisor reset 기록
- 설정 변경 또는 인터페이스 Down 발생 시각

IOS/IOS XE 기반 이중화 장비라면 다음 명령어를 확인할 수 있습니다.

```text
show redundancy
```

스택 구성이라면 다음 명령어를 사용할 수 있습니다.

```text
show switch
show switch stack-ports summary
```

장비와 OS에 따라 위 명령어가 지원되지 않을 수 있으므로, 실행 결과와 모델을 함께 확인해야 합니다.

판단할 내용은 다음과 같습니다.

- Standby가 실제로 `Standby Ready` 상태였는가
- Standby가 HA 제어 링크를 통해 Active를 감지하고 있었는가
- Standby가 이미 초기화되었거나 `Not Ready`, `Init`, `Version Mismatch` 상태였는가
- Active가 꺼진 뒤 Standby가 승격을 시도했는가
- 두 장비의 소프트웨어 버전, 라이선스, 설정이 HA 조건을 만족하는가
- HA 제어 링크 또는 스택 링크가 장애 직전에 끊겼는가

단순히 Active의 전원이 꺼진 것과 HA 전환 실패는 구분해야 합니다. Active가 꺼졌지만 Standby가 정상 승격되었다면 HA 동작은 성공한 것입니다. Active가 꺼진 뒤 Standby가 계속 대기 상태라면 HA 전환 실패입니다.

## 3. Cisco-Juniper 사이 물리 링크 확인

Cisco에서는 연결 포트와 포트채널 멤버를 먼저 식별한 뒤 확인합니다.

```text
show interfaces status
show interfaces <인터페이스>
show interfaces counters errors
```

다음 항목을 확인합니다.

- 인터페이스가 `up/up`인지
- 링크가 Down 된 정확한 시각
- CRC, input error, output error, carrier transition 증가 여부
- 광 모듈 인식 및 속도·듀플렉스 불일치
- 인터페이스 flap 반복 여부
- 포트채널에 속한 모든 멤버의 상태

CDP가 양측에서 활성화되어 있다면 Cisco에서 다음을 확인할 수 있습니다.

```text
show cdp neighbors detail
```

Juniper에서는 Cisco와 혼용하지 않고 다음처럼 확인합니다.

```text
show version
show log messages | last 100
show interfaces terse
show interfaces extensive <인터페이스>
```

확인 항목은 다음과 같습니다.

- Juniper 포트가 `up up`인지
- input/output error, carrier transition, flap 여부
- 광 모듈·속
