아래 순서로 확인하십시오. **링크 Up과 LLDP 인식은 물리 연결 및 이웃 발견만 확인할 뿐, VLAN forwarding과 STP 정상 여부를 보장하지 않습니다.** 장비 모델·OS 버전에 따라 명령어와 STP 구현(PVST+/MSTP/RSTP)이 다를 수 있습니다.

## 1. 변경 전 백업 및 기준 정보 기록

### Cisco IOS 계열
```text
show running-config
show interfaces status
show interfaces trunk
show spanning-tree summary
show mac address-table dynamic
copy running-config startup-config
```

특히 다음 정보를 파일로 저장합니다.

- 트렁크 인터페이스 설정
- allowed VLAN
- native VLAN 및 tagging 방식
- STP 모드와 VLAN별 root/port 상태
- 인터페이스 오류 카운터
- VLAN별 MAC 주소 학습 현황

### Juniper EX/Junos 계열
```text
show configuration | display set
show interfaces terse
show vlans
show ethernet-switching interfaces
show spanning-tree bridge
show ethernet-switching table
```

구성 기록은 다음과 같이 저장할 수 있습니다.

```text
show configuration | display set | save /var/tmp/pre-migration.set
```

Junos 장비의 모델과 OS 버전에 따라 `show ethernet-switching interfaces` 또는 STP 관련 출력 형식이 다를 수 있으므로, 실제 장비에서 지원 여부를 확인해야 합니다. 지원하지 않으면 정확한 명령어 확인이 필요합니다.

## 2. 물리 및 트렁크 기본 확인

양쪽에서 다음을 확인합니다.

1. 동일한 물리 포트가 연결되어 있는지
2. 속도/duplex 오류, CRC, input error, output drop이 없는지
3. Cisco 포트가 trunk이고 Juniper 포트가 해당 VLAN을 전달하는 스위치 포트인지
4. 양쪽의 allowed/member VLAN 목록이 일치하는지
5. native VLAN 또는 untagged VLAN 설정이 일치하는지
6. 한쪽은 tagged, 다른 쪽은 untagged/access 방식으로 동작하지 않는지
7. 해당 링크가 LAG 구성이라면 양쪽의 LAG 구성과 멤버 포트가 일치하는지

### Cisco
```text
show interfaces <인터페이스> switchport
show interfaces trunk
show interfaces <인터페이스>
```

`show interfaces trunk`에서 다음 항목을 비교합니다.

- Vlans allowed on trunk
- Vlans allowed and active
- Vlans in spanning tree forwarding state and not pruned

### Juniper
```text
show configuration interfaces <인터페이스>
show configuration vlans
show ethernet-switching interfaces
```

설정에서 해당 VLAN이 인터페이스에 member로 포함되어 있는지, 태그 방식이 trunk/802.1Q에 맞는지 확인합니다. Cisco의 `switchport trunk allowed vlan`과 Juniper의 VLAN member 설정은 표현 방식이 다르므로 단순히 VLAN 이름만 비교하지 말고 실제 VLAN ID와 포트 적용 상태를 비교해야 합니다.

## 3. 문제가 발생한 VLAN 단위 확인

통신이 되지 않는 VLAN을 하나씩 선정하여 확인합니다.

- 양쪽 VLAN이 실제로 생성되어 있는가
- VLAN ID가 동일한가
- 트렁크 allowed/member 목록에 양쪽 모두 포함되어 있는가
- 해당 VLAN이 STP에서 forwarding 상태인가
- 양쪽 스위치에서 MAC 주소가 학습되는가
- MAC 주소가 정상 포트가 아닌 트렁크 양쪽에서 반복 이동하는가

### Cisco
```text
show vlan brief
show spanning-tree vlan <VLAN-ID>
show mac address-table vlan <VLAN-ID>
show mac address-table dynamic interface <인터페이스>
```

### Juniper
```text
show vlans
show spanning-tree interface <인터페이스>
show ethernet-switching table vlan <VLAN이름>
```

Juniper의 VLAN 조회 명령은 플랫폼과 Junos 버전에 따라 VLAN 이름 기준 또는 다른 형식으로 표시될 수 있습니다. 정확한 명령어 확인이 필요하면 장비 모델과 Junos 버전을 확인해야 합니다.

판단 기준은 다음과 같습니다.

- 트렁크에 VLAN이 없으면 VLAN filtering/member 문제
- VLAN은 있으나 STP가 blocking이면 STP 또는 루프 방지 동작
- STP가 forwarding인데 MAC이 전혀 없으면 단말, VLAN tagging, 경로 문제
- MAC이 짧은 시간에 두 포트 사이에서 이동하면 루프, 이중 연결, LAG 불일치 가능성
- Cisco에서 forwarding인데 Juniper에서 해당 VLAN이 전달되지 않으면 Juniper VLAN member/tagging을 우선 확인
