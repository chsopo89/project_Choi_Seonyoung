다음 순서로 확인하는 것이 안전합니다. 장비 모델과 IOS XE 버전에 따라 일부 출력 형식과 지원 옵션은 달라질 수 있습니다.

## 1. 현재 설정을 먼저 보존하고 확인

먼저 서버 주소를 변경하거나 기존 설정을 삭제하지 말고, 현재 설정과 상태를 확인합니다.

```text
show running-config | include ^ntp|^clock
show clock detail
```

확인할 항목은 다음과 같습니다.

- `ntp server`에 설정된 서버 주소가 무엇인지
- 여러 NTP 서버가 설정되어 있는지
- `ntp source` 설정이 있는지
- NTP 인증 설정이 있는지
- `clock timezone`, `clock summer-time` 설정이 있는지
- 수동 시간 설정이나 기타 시간 관련 설정이 있는지

`show clock detail`은 현재 표시 시간, 표준시/서머타임 적용 여부, 시간 동기화 관련 정보를 확인하는 데 사용합니다. 단순히 표시 시간이 다르다면 NTP 자체가 아니라 timezone 또는 summer-time 설정 문제일 수도 있습니다.

## 2. 실제 NTP 동기화 대상 서버 확인

설정된 서버 목록과 실제 선택된 서버는 다를 수 있으므로 다음 명령을 확인합니다.

```text
show ntp associations
show ntp associations detail
```

주요 확인 항목은 다음과 같습니다.

- 서버 주소 또는 peer 주소
- 상태 기호
  - `*` : 현재 시스템 시간이 동기화된 선택 서버
  - `+` : 동기화 후보이지만 현재 선택 서버는 아님
  - `x` : 문제가 있는 서버로 판단될 수 있음
- `reach` 값
- `stratum`
- `delay`, `offset`, `dispersion`
- reference ID 및 마지막 응답 관련 정보

실제로 시간을 맞추는 서버는 일반적으로 `*`가 표시된 항목입니다. 설정 파일에 서버가 여러 개 있어도 `*`가 특정 서버에 표시되어 있다면 그 서버가 현재 선택된 동기화 대상입니다.

`show ntp associations detail`에서는 설정된 주소와 실제 응답 서버, 피어의 상세 상태를 더 확인할 수 있습니다. 서버 IP가 아니라 DNS 이름을 설정한 경우에도 최종적으로 어떤 주소와 통신 중인지 확인해야 합니다.

## 3. 스위치의 NTP 동기화 여부 확인

```text
show ntp status
```

다음 항목을 확인합니다.

- `Clock is synchronized` 여부
- 동기화된 서버의 주소
- stratum
- reference clock
- 마지막 업데이트 또는 동기화 관련 상태

`Clock is synchronized`가 아니면 서버 설정이 존재하더라도 현재 NTP 동기화가 완료된 상태가 아닙니다. 이 경우 `show ntp associations`의 `reach` 값과 응답 상태를 함께 확인해야 합니다.

`reach` 값은 최근 NTP 응답을 받은 정도를 나타내는 값입니다. 일반적으로 `377`은 최근 통신이 정상적으로 이루어진 상태이고, `0`이면 NTP 응답을 받지 못하고 있음을 의미합니다. 단, 출력 해석은 IOS XE 버전에 따라 세부 형식이 다를 수 있습니다.

## 4. 로컬 시간과 표시 방식 확인

```text
show clock detail
show running-config | include ^clock
```

다음을 구분해야 합니다.

- NTP가 제공하는 기준 시간 자체가 잘못된 경우
- 스위치가 NTP와 동기화되었지만 timezone이 잘못된 경우
- 서머타임 설정이 다른 경우
- 장비 재부팅 후 하드웨어 시계와 시스템 시간이 다르게 보이는 경우

NTP는 기본적으로 UTC 기준 시간을 동기화하고, `clock timezone` 및 `clock summer-time` 설정에 따라 화면에 표시되는 시간이 달라질 수 있습니다. 따라서 다른 장비와 시간 차이가 정확히 1시간 또는 일정한 시간대 차이라면 timezone/summer-time을 우선 의심합니다.

## 5. NTP 서버까지의 네트워크 도달성과 NTP 동기화 구분

먼저 라우팅과 일반 IP 도달성을 확인합니다.

```text
show ip route <NTP-서버-IP>
ping <NTP-서버-IP>
```

이는 다음을 확인하는 단계입니다.

- 서버까지의 라우팅이 존재하는지
- 스위치에서 서버 IP까지 일반 IP 통신이 가능한지

그러나 `ping` 성공만으로 NTP가 정상이라고 판단할 수 없습니다. NTP는 UDP/123을 사용하므로 다음 문제가 별도로 발생할 수 있습니다.

- 중간 방화벽 또는 ACL에서 UDP/123 차단
